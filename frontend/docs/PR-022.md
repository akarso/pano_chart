# PR-022: Chart Event Badge Overlay Specification

## 1. Objective

Add visual macroeconomic event markers directly on price charts.

The goal is to:

* Visually align price action with macro events
* Increase contextual awareness
* Improve perceived intelligence of the app
* Maintain clean, non-intrusive UX

This PR covers:

* Chart badge rendering
* Interaction behavior
* Navigation to Events list
* Filtering logic
* Performance considerations

Non-goals (v1):

* No impact on scoring engine
* No event-based alerting
* No sentiment inference
* No automatic trade suggestions

---

## 2. Data Source

Uses backend endpoint:

GET /api/v1/events

Events must already be normalized and delivered in UTC.

Client responsibilities:

* Convert UTC → local timezone
* Filter events by visible chart window

---

## 3. Badge Rendering Logic

### 3.1 Visibility Rules

An event is rendered if:

* Event timestamp is within chart’s visible time range
* Event impact matches user filter (default: High + Medium)

Optional future toggle:

* “Show Low Impact Events”

---

### 3.2 Visual Representation

Each event is rendered as:

* Thin vertical line spanning full chart height
* Subtle opacity (not blocking candles)
* Color-coded by impact:

High → Red
Medium → Orange
Low → Grey

Line width must remain minimal to avoid visual clutter.

---

### 3.3 Stacking Logic

If multiple events share identical timestamp:

* Merge into single vertical line
* Show count indicator (small dot or badge above line)
* Overlay lists all events

---

## 4. Interaction Model

### 4.1 Tap Behavior

On tap of event line:

* Small overlay appears above chart
* Overlay includes:

  * Event title
  * Country
  * Impact
  * UTC time
  * Local time
  * Close button

Overlay must:

* Not block entire chart
* Be dismissible via tap outside or close button
* Animate smoothly (fade/slide)

---

### 4.2 Navigation

If user taps overlay body:

* Navigate to Events List screen
* Scroll to exact event
* Highlight event row briefly

This creates a clean loop between chart and list.

---

## 5. Events List Deep Linking

Events list must support:

* Scroll-to-event by ID
* Temporary highlight state
* Smooth UX without jumpiness

Deep link structure (internal only):

events/{event_id}

---

## 6. Filtering Controls (Chart Level)

In chart settings panel:

Toggle options:

* Show Events (On/Off)
* High Only
* High + Medium (default)
* All

Default: High + Medium

Preference persisted locally.

---

## 7. Performance Considerations

* Events must be pre-fetched before chart loads
* Rendering must not trigger full chart re-draw
* Badge drawing should be lightweight overlay layer
* Avoid per-frame recalculation

Recommended:

* Cache visible events after filtering
* Recalculate only when chart timeframe or visible range changes

---

## 8. Timeframe Behavior

Events are timeframe-agnostic.

Example:

If chart timeframe is 1m:

* Event line still rendered at exact timestamp

If timeframe is 4h:

* Event appears aligned to containing candle

No scaling logic required.

---

## 9. Edge Cases

### 9.1 Event Outside Visible Range

Do not render.

### 9.2 Event Exactly Between Candles

Snap to nearest candle open time.

### 9.3 Dense Event Clusters

If more than 5 events within 2-hour window:

* Slightly reduce opacity
* Merge visually where overlapping

Avoid clutter at all cost.

---

## 10. Future Extensions (Not in This PR)

* Countdown badge (“Event in 2h”)
* Proximity warning
* Event severity heat zones
* Algo awareness flag
* Push notifications

---

## 11. Acceptance Criteria

* Events appear as vertical lines on chart
* Color-coded by impact
* Tappable overlay works
* Overlay deep-links to list
* No noticeable chart performance degradation
* Filter toggle works and persists

---

## 12. UX Philosophy

Events must:

* Inform
* Not overwhelm
* Never dominate chart
* Always remain contextual

Chart remains primary.
Events remain secondary layer.

---

END PR-022
