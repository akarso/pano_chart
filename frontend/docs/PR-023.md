# PR-023: Market Overview Bubble Map Specification

## 1. Objective

Introduce a Market Overview Bubble Map screen to provide an intuitive, high-level visualization of the current crypto market state.

Goals:

* Deliver instant market sentiment overview
* Improve app stickiness and perceived value
* Provide entry point into detailed token analysis
* Keep interaction simple and responsive

Non-goals (v1):

* No historical playback
* No advanced clustering
* No heatmap sector grouping
* No animated transitions between timeframes

---

## 2. Concept

Each token is represented as a bubble.

Bubble characteristics:

* Size → Relative Volume (24h)
* Color → Price Change (24h)
* Optional Border/Glow → Regime State (Sideways / Compression / Breakout)

The bubble map acts as:

* A discovery tool
* A macro snapshot
* A visual filter before entering screener mode

---

## 3. Data Requirements

Backend must provide:

GET /api/v1/market-overview

### Response Structure

```json
{
  "tokens": [
    {
      "symbol": "BTCUSDT",
      "price_change_24h": 2.4,
      "volume_24h": 28400000000,
      "market_cap": 950000000000,
      "sideways_score": 0.32,
      "compression_score": 0.12,
      "breakout_score": 0.05
    }
  ]
}
```

Minimum required for v1:

* symbol
* price_change_24h
* volume_24h

Regime scores optional but recommended.

---

## 4. Bubble Sizing Logic

### 4.1 Primary Metric

Default: 24h Volume
Secondary: price change 24h
(this must be switchable, probably from the settings menu via dropdown)

Reason:

* Volume gives activity weight
* Avoids dominance of low-liquidity tokens

### 4.2 Normalization

Use logarithmic scaling to prevent BTC/ETH dominance.

Example:

```
size = log(volume) normalized to screen area range
```

Minimum bubble size must remain visible.

When switching bwetween volume/price change sorting, apply scaling accordingly.

Volume sorting: bubble size according to volume, color according to price change
Price change sorting: bubble size according to price change, color according to price change

---

## 5. Color Logic

### 5.1 Price Change Mapping

* Positive → Green scale
* Negative → Red scale
* Near zero → Neutral grey

Color intensity proportional to magnitude.

Clamp extreme values to avoid visual distortion.

---

## 6. Regime Overlay (Optional but Recommended)

If regime scores available:

* Sideways dominant → Thin blue border
* Compression dominant → Yellow border
* Breakout dominant → Purple border

Only one regime shown (highest score).

Threshold:
Minimum regime score = 0.5 to display overlay.

---

## 7. Interaction Model

### 7.1 Tap

On bubble tap:

* Navigate to Detail View for symbol
* Preserve current timeframe
* Smooth animation transition

### 7.2 Long Press (Optional Future)

* Quick preview card
* Basic stats

Not required for v1.

---

## 8. Filtering Controls

Top bar controls:

* Timeframe selector (1m, 5m, 15m, 1h, 4h, 1d)
* Page filter (Top 50 / 51 - 100 / 101 - 150)
* Sort toggle (Volume / Change / Regime)

Default:
15m timeframe + Top 50.

---

## 9. Layout Algorithm

Use simple force-directed or grid-based packing algorithm.

Requirements:

* No overlapping bubbles
* Smooth physics-based settling
* Stable layout (avoid chaotic reshuffling on refresh)

Refresh behavior:

* Data refresh on pull down
* Smooth size/color transition (animated)

Paging:

* For now, three pages: 1 - 50, 51 - 100, 101 - 150, switchable from dropdown

---

## 10. Performance Constraints

* Max 50 bubbles per screen
* Avoid per-frame recalculation
* Precompute normalized sizes before rendering

Flutter Implementation Recommendation:

* CustomPainter or Canvas-based rendering
* Avoid heavy widget trees per bubble

---

## 11. Edge Cases

### 11.1 Extreme Market Move

If market-wide dump or pump:

* Maintain color range clamping
* Avoid full-screen uniform red/green

### 11.2 Low Liquidity Tokens

If volume below threshold:

* Either exclude
* Or apply minimum bubble size

Decision recommended:
Exclude tokens below liquidity threshold.

---

## 12. UX Philosophy

Bubble map must feel:

* Calm
* Informative
* Not chaotic
* Not casino-like

No flashing.
No rapid pulsing.
No exaggerated animations.

---

## 13. Future Extensions

* Market sentiment index

---

## 14. Acceptance Criteria

* Bubble map loads within 1 second
* No overlapping bubbles
* Tap navigation works reliably
* Data refresh does not cause layout chaos

## 15. Strategic Impact

Bubble map:

* Enhances marketing appeal
* Improves onboarding experience

This screen should become the default landing page for new users.
