# PR-024: Detail View Chart Engine Upgrade (Div-Based, Scalable, Multi-Indicator)

## 1. Objective

Rebuild the Detail View chart using a div-based layout (not CustomPainter) to enable:

* Horizontal pinch-to-zoom scaling
* Clean overlay layering
* Configurable technical indicators
* Responsive axes
* Modular extensibility

The chart must feel lightweight, interactive, and structurally clean — not a canvas experiment.

---

## 2. Layout Architecture

### 2.1 Container Hierarchy

Root container:

* position: relative
* width: 100%
* height: configurable (responsive)
* overflow: hidden

Inside:

1. Chart Layer (candles + EMA clouds + event lines)
2. Axes Layer (x & y labels)
3. Volume Layer (below chart)
4. Oscillator Layer (RSI + optional ATR)
5. Interaction Layer (gestures, overlays)

All internal layers use:

* position: absolute
* relative units (% / logical pixels scaled)
* dynamic recalculation on zoom

---

## 3. Candle Rendering Model

Each candle:

* Wrapper div (absolute positioned)
* Body div
* Wick div

### 3.1 Wick

* Fixed width: 1px
* If zoom scale > threshold → 2–3px
* Height based on high/low relative to chart range

### 3.2 Body

* Width based on horizontal scale factor
* Min width enforced
* Color:

  * Bullish → green
  * Bearish → red

No gradients.
No shadows.
Keep it structural.

---

## 4. Scaling & Gestures

### 4.1 Horizontal Zoom (Pinch)

* Two-finger pinch gesture
* Adjust candle width
* Limit min/max zoom boundaries

Zoom limits:

* Min: 20 candles visible
* Max: 200 candles visible

### 4.2 Panning

* Horizontal drag
* No vertical pan (price auto-scales)

### 4.3 Y-Axis Behavior

* Dynamic auto-scale to visible range
* Maintain 5–7 visible grid levels
* Smooth transition on zoom

Axes must never stretch or distort.

---

## 5. Volume Layer

Positioned below main chart.

* Fixed height: 20–25% of chart area
* Bars aligned with candles
* Color matches candle direction
* Volume normalization relative to visible window

No smoothing.

---

## 6. RSI Overlay

### 6.1 Location

Overlaid on Volume Layer (shared panel).

### 6.2 Features

* Line chart
* 30 and 70 horizontal reference levels
* Optional 50 midline
* Distinct color from volume

### 6.3 Configurable

* Enable/Disable
* Period (default 14)
* Show/hide 30/70

---

## 7. EMA Clouds

Overlaid directly on price chart.

### 7.1 Configuration

* Fast EMA (default 20)
* Slow EMA (default 50)
* Enable/Disable individually

### 7.2 Cloud Rendering

* Area between EMAs shaded
* Color:

  * Bullish alignment → green tint
  * Bearish alignment → red tint
* Opacity low to avoid candle obstruction

---

## 8. ATR (Optional)

Rendered in oscillator panel (same as RSI).

### 8.1 Display Mode

* Line chart
* Normalized to visible price scale
* Optional ATR moving average

### 8.2 Configurable

* Enable/Disable
* Period (default 14)

ATR should not dominate RSI visually.

---

## 9. Indicator Configuration Panel

Accessible via settings icon.

Options:

* Toggle RSI
* Toggle EMA Fast
* Toggle EMA Slow
* Toggle ATR
* Adjust RSI period
* Adjust EMA periods
* Adjust ATR period

Persist settings locally per user.

---

## 10. Performance Constraints

* Max visible candles: 250
* Avoid rebuilding entire widget tree on every frame
* Use repaint boundaries
* Only recalc on:

  * Zoom change
  * Pan
  * Indicator toggle
  * New data

Target:
Smooth 60fps interaction.

---

## 11. Event Badge Compatibility

Event lines must:

* Render in Chart Layer
* Respect zoom/pan transforms
* Remain tappable
* Not scale thickness excessively

Overlay behavior from PR-022 remains unchanged.

---

## 12. Axes & Labels

### 12.1 X-Axis

* Time labels adaptive to timeframe
* Avoid overlapping text
* Dynamic spacing

### 12.2 Y-Axis

* Price labels right-aligned
* Clean formatting (2–6 decimals adaptive)
* Stable during pan

---

## 13. Edge Cases

### 13.1 Extreme Zoom

If candle width < 1px:

* Enforce minimum width
* Do not render fractional widths

### 13.2 Very Low Volatility

Ensure bodies are visible even if tiny.
Enforce minimum body height.

### 13.3 Large Wick Range

Wicks must not exceed container.
Clamp visually.

---

## 14. UX Philosophy

Detail view must:

* Feel precise
* Feel calm
* Avoid TradingView complexity
* Provide confirmation, not analysis overload

The regime engine remains primary decision layer.
Indicators are supportive.

---

## 15. Acceptance Criteria

* Smooth pinch-to-zoom horizontally
* Stable axes during interaction
* Volume aligned with candles
* RSI renders correctly with levels
* EMA clouds overlay cleanly
* ATR optional and non-intrusive
* Indicators configurable and persistent
* No visible performance degradation

---

## 16. Strategic Impact

Detail View Upgrade achieves:

* Professional feel
* Increased user confidence
* Reduced bounce after tap
* Alignment with trader expectations

This is the first step toward making the app feel like a real trading terminal — without becoming one.
