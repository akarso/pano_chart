# PR-027: Trade Action Buttons Integration (TradingView + External Apps)

## 1. Objective

Add lightweight, zero-permission trade action buttons to Detail View:

* Open in TradingView
* Trade in External App

Design goals:

* No suspicious permissions
* No API keys
* No wallet access
* No background integrations
* Pure deep linking only

This must feel safe and transparent.

---

## 2. UI Placement

Location:

Below chart, above metadata section.

Buttons:

[ Open in TradingView ]   [ Trade in App ]

Optional future:
User selects preferred trading app in settings.

---

## 3. TradingView Integration

### 3.1 Strategy

Use standard web deep link.

Example format:

https://www.tradingview.com/chart/?symbol=BINANCE:ETHUSDT

If timeframe supported:

Append interval parameter:

&interval=15

Timeframe mapping:

1m → 1
5m → 5
15m → 15
1h → 60
4h → 240
1d → D

### 3.2 Behavior

* Open in system browser
* If TradingView app installed, OS handles redirect
* No special permissions required

---

## 4. External Trading App Integration

### 4.1 Architecture Philosophy

We DO NOT:

* Integrate SDKs
* Request wallet permissions
* Embed webviews with login
* Handle private APIs

We ONLY:

* Deep link to exchange app if supported
* Otherwise open exchange website

This keeps app trust high.

---

## 5. Integration Strategy

### 5.1 Method A: Known Deep Links (Best Case)

If exchange supports URL schemes:

Example (hypothetical):

mexc://trade/ETH_USDT?interval=15m

Implementation:

* Attempt app scheme
* If fails → fallback to https URL

Requires:

* Exchange documentation

---

### 5.2 Method B: HTTPS Fallback (Most Realistic)

Most exchanges behave like PWAs.

Use:

https://www.mexc.com/exchange/ETH_USDT

System will:

* Open app if installed
* Otherwise open browser

Timeframe control often NOT supported via URL.

---

## 6. Symbol Mapping Layer

Backend must expose standardized mapping:

Example:

Internal: ETHUSDT
TradingView: BINANCE:ETHUSDT
MEXC: ETH_USDT

Create mapping struct:

```go
type ExchangeMapping struct {
    SymbolInternal string
    TradingView    string
    MEXC           string
    Binance        string
}
```

App resolves correct format before deep linking.

---

## 7. Timeframe Passing

Reality check:

Most exchange apps do NOT support timeframe via URL.

Therefore:

* Pass timeframe only to TradingView
* External apps open default timeframe
* User changes manually

This is acceptable UX.

---

## 8. App Selection Model

### 8.1 Default Behavior

Pressing “Trade in App”:

* Show OS chooser (Android)
* Or use stored preferred exchange (iOS)

### 8.2 Settings Screen

Allow user to:

Select preferred exchange:

* Binance
* MEXC
* Bybit
* Other (future)

Persist locally.

---

## 9. Security Considerations

This implementation:

* Requests ZERO extra permissions
* Does NOT access trading accounts
* Does NOT handle user credentials
* Does NOT inject trading data

All trading occurs externally.

App remains informational tool.

---

## 10. Edge Cases

### 10.1 App Not Installed

Fallback to web version.

### 10.2 Unsupported Symbol

Show simple toast:
“Symbol not supported on selected exchange.”

### 10.3 Futures vs Spot

If needed:
Add toggle in settings:

* Spot
* Perpetual

Mapping must handle this.

---

## 11. Acceptance Criteria

* TradingView opens correct symbol + timeframe
* Trade in App opens correct exchange page
* No additional permissions required
* No crashes if app not installed
* Symbol mapping works correctly
* UX feels seamless

---

## 12. Strategic Impact

This feature:

* Increases conversion from research → action
* Keeps app trust intact
* Avoids regulatory and security risks
* Makes product feel complete

You are not becoming an exchange.

You are becoming the intelligence layer before execution.
