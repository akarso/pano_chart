# PR-015 — Sideways Algorithm v2 + Algorithm Switching

## Goal

Improve the Sideways Consistency Score so that rankings visually match human perception of a structured horizontal channel.

Additionally, introduce runtime algorithm switching (v1 / v2) for safe comparison and tuning.

After this PR:

* Sideways v2 exists alongside v1
* Rankings endpoint can switch sideways implementation
* Visual alignment between ranking and chart improves
* No breaking changes to API contract

---

# Background

Current Sideways v1 detects:

* Low net displacement
* Stable volatility
* High oscillation frequency

Formula:

```
score = (1 − NDR) × RSS × ODS
```

This effectively detects high-frequency chop.

Problem:

It does not explicitly measure channel structure or boundary respect, so results may look visually noisy rather than clearly range-bound.

---

# Design Philosophy for v2

Sideways v2 should detect:

* Low directional drift
* Clear horizontal boundaries
* Repeated interaction with upper and lower bands
* Reasonable channel width
* Limited slope bias

The goal is structural sideways detection, not micro-chop detection.

---

# Sideways v2 Components

All computations must be O(n) over the candle window.

Minimum required candles: 6 (same as v1).

---

## 1️⃣ Flatness Score (FS)

Reuse Net Displacement Ratio (NDR).

```
FS = 1 − NDR
```

Ensures price ends near where it started.

---

## 2️⃣ Channel Tightness Score (CTS)

Compute:

```
range = max − min
normalized_range = range / mean_price
```

Define an ideal channel width band, for example:

* Ideal mid: 5%
* Acceptable tolerance: ±3%

Score:

```
CTS = 1 − abs(normalized_range − ideal_mid) / tolerance
CTS clamped to [0,1]
```

Penalizes:

* Flatline (too narrow)
* Explosive swings (too wide)

---

## 3️⃣ Boundary Respect Score (BRS)

Compute:

* upper_band = 90th percentile close
* lower_band = 10th percentile close
* epsilon = 10% of total range

Count touches:

```
touch_upper = count(close >= upper_band − epsilon)
touch_lower = count(close <= lower_band + epsilon)
```

Score:

```
BRS = min(touch_upper, touch_lower) / expected_touch_count
BRS clamped to [0,1]
```

Ensures repeated interaction with both boundaries.

---

## 4️⃣ Slope Neutrality Score (SNS)

Compute linear regression slope over closes.

Normalize:

```
normalized_slope = abs(slope) * window_length / range
```

Score:

```
SNS = 1 − normalized_slope
SNS clamped to [0,1]
```

Penalizes directional drift.

---

# Final Sideways v2 Formula

Use additive blend (not multiplicative):

```
score =
  0.35 * FS  +
  0.25 * BRS +
  0.20 * SNS +
  0.20 * CTS
```

Optional noise penalty:

If Oscillation Density Score (ODS) > 0.8:

```
score *= 0.85
```

This reduces ranking of ultra-noisy micro-chop.

---

# Algorithm Switching

Introduce configurable algorithm selection.

Options:

* Environment variable (preferred):

```
SIDEWAYS_ALGO=v1 | v2
```

* OR debug query parameter (optional):

```
/api/rankings?...&sidewaysAlgo=v2
```

Implementation:

```
switch config.SidewaysAlgo {
  case "v1": score = sidewaysV1(candles)
  case "v2": score = sidewaysV2(candles)
}
```

Default remains v1 until validation confirms v2 improvement.

# Constraints

Do NOT:

* Remove v1
* Change API schema
* Increase computational complexity beyond O(n)

All changes remain internal to scoring layer.
