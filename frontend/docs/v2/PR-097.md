## PR-097: feat(overview): Leaders / Laggards + RS chip

🎯 Objective

Let users sort the overview grid by relative strength versus the market
composite, and show a small RS chip on tiles when the backend scored it.

See ROADMAP Track C — PR-097. Depends on PR-096.

🧱 Scope

- Rankings DTO / `OverviewItem` / `OverviewResult` — `rs`, `beta`, `rsRank`,
  `rsAvailable`
- `overview_view_model.dart` — `leaders` / `laggards` sort (nulls last)
- Sort menu — "Leaders (vs market)" / "Laggards (vs market)" (Pro)
- `RelativeStrengthChip` — bottom-right; tap → info dialog
- Offline cache encode/decode for the new fields

Out of scope: backend RS math (PR-096); sector rotation (PR-098).

1️⃣ Data

Parse `rsAvailable` and per-row `rs` / `beta` / `rsRank` (nullable; omitempty).
Chip gate: `rsAvailable && rs != null` (real `0` still shows).

2️⃣ Sort

`leaders` = highest `rs` first; `laggards` = lowest first; unscored last.

3️⃣ Chip

`+3.2% vs mkt` / `−1.1% vs mkt` (`rs × 100`, one decimal), green/red.
Tap explains relative strength and beta.

✅ Definition of Done

- [x] DTO / mapping tests for RS fields
- [x] View-model sort order with three fakes; nulls last; fallback keeps backend order
- [x] Chip hidden when `rsAvailable=false` or `rs` omitted; shown for `rs: 0`
- [x] Cache round-trip for RS fields; refresh writes cache; sort-mismatch ignored
- [x] flutter test clean for overview / chip tests

🚀 Result

Pro users can sort Leaders/Laggards and see excess return versus the tape on
each tile when the backend marks RS available. When a response reports
`effectiveSort` ≠ requested leaders/laggards, the menu shows Total and the
grid keeps backend order (not A–Z). The menu does not flash Total before the
first response. Favourite merges never promote a fallback board.
