## PR-100: feat(detail, overview): MTF strip and aligned badge

🎯 Objective

Surface the multi-timeframe regime stack (PR-099) in two places: a per-symbol
pill strip on the detail screen, and an "aligned" badge/sort on the overview
grid.

See ROADMAP Track D — PR-100. Depends on PR-099 (`GET /api/symbol/{symbol}/regimes`,
`GET /api/rankings?mtf=1`).

🧱 Scope

- `MtfRegimesData` / `MtfFrame` — parse `GET /api/symbol/{symbol}/regimes`
- `HttpMtfRegimesApi` — 15s timeout, matches the other per-symbol detail APIs
- `regime_colors.dart` — shared `regimeColor`/`trendBiasColor`/`trendBiasIcon`,
  extracted out of `MarketPulseScreen` so Market Pulse, the overview badge,
  and the detail strip can never disagree about what a regime looks like
- Detail screen: 4-pill strip (`15m · 1h · 4h · 1d`), fetched once per symbol
  (not reloaded on chart timeframe switch — the stack itself is fixed-timeframe);
  pro-gated like fragility/behavior/volatility
- `RankingItemDto` / `OverviewItem` — nullable `alignment`/`alignedState`
  (PR-096/097 nullable-field pattern); overlay requested (`?mtf=1`) only for
  entitled users (`OverviewViewModel.isProUser`, synced from the widget
  before every fetch) — unlike RS, the overlay has a real per-row backend
  cost, so free users must not pay for a feature they can't see
- Overview tile: colored top border + tooltip when `alignment >= 0.75`,
  pro-gated (matches the existing RS chip's `showRsChip: _isProUser` gate);
  `Card.margin` zeroed so the border actually hugs the tile edge
- Sort mode `aligned`: alignment desc, then total score desc — fixed order,
  not in `kDirectionalSorts`

Out of scope: backend MTF stack (PR-099); notification alerts on transitions (PR-101).

1️⃣ Detail strip

Each pill colored by that timeframe's dominant regime; a missing/stale/
algo-mismatched frame renders as a neutral placeholder pill (not omitted —
the strip always shows all 4 slots). The bias arrow shows on every real
pill regardless of dominant regime (sideways/compression/expansion can
still lean up or down) — only a missing/placeholder pill has nothing to
show one for.

2️⃣ Aligned badge

Border color is `regimeColor(alignedState)`. Tooltip text ("Aligned: trend
(75%)") shows the alignment ratio as a percentage rather than a "N/4" frame
count — the overlay only reports the ratio, not raw frame counts, and a
symbol with fewer than 4 fresh frames makes "N/4" ambiguous (ratio 1.0 could
mean 1/1, 2/2, 3/3, or 4/4); the percentage has no such failure mode.
Reaching the Bubble Map screen, or opening a setup notification, from a free
account no longer carries the API through to its own `DetailScreen` push
(both were ungated pre-fix; the direct overview → detail path was already
correctly gated) — all three `DetailScreen` construction sites now agree.

The strip also now recovers, without over-correcting into needless
re-fetching: `_mtfFetched` is only ever set on success, so a failed attempt
leaves the door open for a retry (via `_loadMtfRegimes()`'s own guard)
while a successful, symbol-scoped reading is left alone. Both the manual
"Reload chart" button (all tiers) and the pro-only auto-refresh tick call
`_loadMtfRegimes()` unconditionally — the guard decides whether that's a
retry or a no-op. There is no "newest dispatch wins" guard: rejecting a
response just because a differently-ordered concurrent attempt was
dispatched later would discard a valid success whenever that later attempt
fails first. Instead, a monotonic "last *applied* sequence" tracks what's
already on screen, so a success is applied only if it isn't older than the
current reading — an older call's success still lands when nothing newer
ever succeeds, but it can no longer overwrite a newer success that already
landed (PR-100 CR).

3️⃣ Sort

`aligned` reorders locally (client-side, like every other sort mode here);
nulls treated as 0 alignment, so unscored rows sort last. Unlike
leaders/laggards, the backend doesn't recognize `sort=aligned` and falls
back to its own default before paginating, so a local re-sort of only the
fetched page(s) could strand a highly-aligned symbol on a later,
not-yet-fetched page. `OverviewViewModel` auto-completes pagination
(fire-and-forget, generation-guarded) whenever `aligned` is active so the
local sort always operates over the full result set. That loop also stops
(rather than looping forever) when a page fetch fails, since a failed
`loadNext` call leaves `page`/`hasMore` unchanged and would otherwise
immediately re-request the identical page.

🚀 Result

The detail screen shows at a glance whether a symbol's regime agrees across
timeframes, and the grid highlights strongly-aligned symbols without an
extra request — the overlay reuses the same page fetch, requested only for
entitled users so free accounts never pay the backend's per-row store-read
cost for a feature gated out of their view entirely.
