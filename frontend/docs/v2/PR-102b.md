## PR-102b: Contextual alert payloads (frontend)

**Layer:** frontend. **Depends on:** PR-102a.

### Scope

- Parse FCM / local-notification `data["context"]` into an `AlertContext`
  model (tolerant of missing fields and bad JSON).
- When `context.sparkline` is present, render a mini sparkline to PNG
  (`PictureRecorder` → `ui.Image` → PNG bytes) and show the foreground
  local notification with Android `BigPictureStyleInformation`.
- Wire `FirebaseMessaging.onMessage` in `main.dart` to await
  `NotificationService.show` (catch errors). Tap routing is unchanged
  (timeframe already forwarded for market / setup / watchlist in PR-101b).
- iOS keeps title/body only (no rich attachment in this PR).
- Background / killed delivery stays system-tray title/body; sparkline
  closes in `context` are unused until a follow-up (data-message + local
  notif, or FCM image URL). Documented in COMMON.md.
- Client caps sparkline length at 30 before paint; `show` catches PNG
  failures and falls back to plain details.

### Out of scope

Backend context attachment (PR-102a). Composite-index sparkline for
market-only alerts. Changing `NotificationRouter` deep-link targets.
Background rich notifications.

### Tests

- `AlertContext.fromJson` / `fromDataString` / `fromPayload`: happy path,
  missing fields, malformed JSON, map-shaped context, length cap
- Sparkline PNG renderer returns non-empty bytes for a 30-point series
- `NotificationService.buildDetails` uses big-picture Android details when
  sparkline bytes are provided
- `NotificationService.resolveDetails` / `show` fall back to plain details
  when the PNG renderer throws (fail-open)
- Router still navigates with timeframe when `context` is present on the
  payload
