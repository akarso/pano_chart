## PR-093: feat(frontend): reliability chips and scorecards screen

🎯 Objective

Show graded hit rate next to the calls the app already makes, and give a
place to read the deciles. Chips stay hidden until a label has 30 graded
outcomes.

See ROADMAP Track B — PR-093.

🧱 Scope

- `features/scorecards/` — JSON models, HTTP client, chip, list + decile screen
- Overview settings → Reliability
- Chip beside the rankings badge, the Market Pulse regime headline, and the
  setup card
- Market Pulse regime info dialog links to the same screen

Out of scope: backend scorecard math, auth, and a per-symbol history view.

1️⃣ Data

`GET /api/scorecards/summary?timeframe=&since=30d` feeds every chip.
`baseline: null` stays null (grey chip, chance shown as —). Numeric `0` stays
zero. Badge / setup / regime labels match the strings the backend logs.

2️⃣ Chip

`58% · n=412`. Green when hit rate − baseline ≥ 0.05, red when it trails by
more than 0.05, grey inside that band. Hidden when `n < 30`. Tap explains
"Of the last N times the app showed this, X% worked out. Chance: Y%."

3️⃣ Screen

Settings (gear) → Reliability lists every `(kind, label)` for the last 30
days, including small samples. Tap a row for the decile bars.

✅ Definition of Done

- [x] Chip color thresholds and hidden-when-small-n widget tests
- [x] JSON parsing of null baseline, numeric zero, and deciles
- [x] Chips on badge, regime headline, and setup card
- [x] Settings and Market Pulse info dialog open the list
- [x] flutter test clean for the scorecard tests

🚀 Result

A label with enough graded outcomes shows its hit rate in place. The list
shows the same window's deciles.

📝 Implementation notes

- One summary request per timeframe change. A newer request drops an older
  response. A timeframe change clears chips, and a failed reload of the same
  timeframe keeps the summary already on screen.
  Detail does not refetch on the candle timer, and skips the summary when
  there is no setup card to label.
- Setup chips appear only when confidence is at least 0.5, next to the
  mapped label. A timeframe change hides the setup card until that
  timeframe's fetch finishes, and a stale or failed fetch does not restore
  the previous card. A chart refresh for a timeframe that is no longer
  showing does not write its candles or reload setup. A timeframe change
  clears fragility, behavior, and volatility with the candles. A failed fetch
  for the new timeframe does not put the previous payload back, and a body
  whose timeframe does not match the request is ignored and does not clear a
  panel that already matches the screen. Reload retries those
  three with setup. A failed reload of the same summary keeps the chips
  already showing. Regime copy counts regime changes.
- The reliability list uses `sinceRaw`, retries after an error, and the row
  tap opens deciles.
