## PR-101b: Watchlist frontend — star toggle, filter chip, alert settings

🎯 Objective

Surface the backend watchlist (PR-101a) in the app: starring a symbol makes
the scheduler track it for regime-transition alerts, a "Watchlist" chip
filters the grid to starred symbols, and a settings row lets pro users
control the alert.

See ROADMAP Track D — PR-101 (frontend half). Depends on PR-101a
(`GET/PUT/DELETE /api/watchlist`, `watchlist_transitions`/
`watchlist_timeframe` on `/api/notification/config`).

🧱 Scope

**Unified with the existing "favourites" feature**, not a parallel one —
the app already had a local-only star (tile + detail screen +
`PreferencesService.favourites`) with a nav-bar toggle that filtered the
grid. That star *is* the watchlist now. One `WatchlistController`
(composition root) owns the set. Overview, detail, Bubble Map, and the
notification loader all read and write that instance. The grid does not
learn about a detail-screen star from `Navigator.pop`.

- `WatchlistApi` (port) / `HttpWatchlistApi` (impl) — `fetch`/`replace`/
  `remove` against `GET/PUT/DELETE /api/watchlist`. Not pro-gated — every
  user can star a symbol; only the alert is pro-only. Non-200 responses
  throw `HttpWatchlistApiException` with the status code and body. A
  symbol entry that is not a string is the same exception, not a
  `TypeError`.
- `WatchlistController` queues fetch and toggle one at a time.
  `serverSnapshotKnown` is set only after a fetch or a push returns.
  Until then the controller does not PUT: replace deletes every server
  symbol absent from the body, and this device may not have seen them.
  A toggle made while the snapshot is unknown stays pending. If that
  fetch fails, the star stays and the snackbar says it is not on the
  server yet. The next successful fetch merges it. Resume after the app
  was paused refetches; a transient inactive (notification shade) does
  not. A timed-out PUT/DELETE closes the socket and refetches. If that
  refetch already has the edit, it is kept. If not, the diff is pushed
  once and fetched again. When the edit is still absent, the star stays
  and the snackbar says it is not on the server yet. A response for an
  older toggle is dropped.
- **Upgrade.** The first successful fetch unions the local cache with
  the server list and PUTs that union once, at most 50 symbols. This
  device's stars fill those slots before the server's. Symbols past 50
  are named in the snackbar and left off. Invalid symbols are skipped
  and every skipped name is in the snackbar. `watchlistMigrated` is set
  only after that upload is what got stored. A failed upload keeps
  pending adds and removals and retries the same union. A symbol is
  dropped only when the response names it as invalid. After a named
  invalid is dropped, the cap is rebuilt so a server symbol that now
  fits is kept. A full payload the server calls too large, or an
  unrecognized 400, is remembered across restarts with the pending
  sentence and is not sent again. A later empty server list means the
  user cleared it.
- The tile star is an `IconButton` with a tooltip. It is 48px when the
  card has room. On a short phone tile the name sits beside the star
  when the badge leaves room, otherwise on the top row with the star
  below. That layout is checked at 320 and 390 for 2 and 3 columns,
  including a badged 3-column tile, and for 1 column.
  The client stops at 50 symbols (`Watchlist is full (50 symbols).`).
  HTTP 400 uses that copy only when the body says the list is too
  large. An invalid symbol has its own message. HTTP 429 uses a
  rate-limit message. Other failures use `Could not update watchlist`.
- Nav bar: `FilterChip` labeled "Watchlist". If that chip is on when
  reconcile changes the set, the grid loads symbols that were not on
  the first page.
- `watchlist_transition` opens the symbol's detail screen. An empty
  symbol does not navigate. The route is suppressed when the alert
  toggle is off.
- `NotificationSettings` gains `watchlistTransitions` (bool, default
  `true`) / `watchlistTimeframe` (string, default `'1h'`). The timeframe
  is the MTF strip set (`kMtfStripTimeframes`: `15m`, `1h`, `4h`, `1d`).
  `applyFromJson` ignores anything else. The prefs getter returns a
  clamped value and does not write. The setter stores the clamped
  value. The settings row is inside the pro-gated block — the scheduler gates the
  alert on `userHasProAccess`.

### Out of scope

Contextual alert payloads / big-picture notification rendering with a
sparkline (PR-102).

### Tests

- `HttpWatchlistApi`: fetch/replace/remove happy paths, auth header
  injection, non-200 throws for each method, a non-string symbol throws
  `HttpWatchlistApiException`, a timeout closes the client opened for
  that call
- `WatchlistController`: empty-server upgrade (upload once, then an
  empty list clears), a non-empty server list is unioned with the local
  cache on the first fetch, a cache over 50 uploads the first 50 and
  does not retry, an oversized union keeps this device's stars, an
  invalid symbol is skipped and several skipped names are all reported,
  a failed upgrade keeps a pending removal and a pending add, a
  too-many upgrade response does not drop local stars, fetch-failure-then-add
  stays pending and does not PUT the local cache, a same-turn toggle
  merges onto the server list, a response for an older toggle is
  dropped, timeout after the server committed keeps the symbol, a
  timeout that does not change the server stays pending, the 51st
  symbol is rejected locally, an empty symbol is rejected, 400 "too many"
  and 429 use different copy
- `NotificationSettings`: `watchlistTransitions`/`watchlistTimeframe`
  round-trip; an out-of-range timeframe is ignored on read and on write
- `NotificationSettingsPage`: watchlist row shown for pro / hidden for
  free, restricted to the four MTF timeframes, toggle persists to prefs
- Overview grid: star add PUTs and star remove DELETEs; the chip
  filters to starred symbols; the first fetch unions a local star with
  the server list; an empty server list uploads local stars; the chip
  loads the server set if it was turned on during startup; the tile
  star is 48px on a wide grid and at least 32px on a 3-column phone
  with the RS chip; a notification shade does not fetch again; Bubble Map and the
  notification loader hold the same controller
- Detail screen: star toggle goes through the controller; a symbol
  already in the controller renders starred; a failed sync rolls back
  and shows the controller's message
