## PR-039: feat(subscriptions): pro gating, subscription states, and capability-based access
🎯 Objective

Introduce a robust subscription system with:

14-day free trial (via Google Play)
automatic downgrade to free tier after expiration
centralized feature gating via capabilities
backend-driven subscription state (source of truth)
clean UX (no aggressive upselling)

🧱 Scope

This PR introduces:

- subscription state model (backend)
- capability-based feature gating (frontend)
- free vs pro feature separation
- push notification filtering by subscription
- restore purchases support
- minimal paywall entry points
- analytics hooks

1️⃣ Subscription Model (Backend)
New table
user_subscription
-----------------
user_id
status          -- FREE | TRIAL | ACTIVE | GRACE | EXPIRED
expiry_date
platform        -- android (ios later)
product_id
updated_at

State behavior
TRIAL        → full PRO access
ACTIVE       → full PRO access
GRACE        → full PRO access (optional fallback)
EXPIRED/FREE → free tier
Backend is source of truth

Flow:

App → purchase (Google Billing)
→ sends purchaseToken to backend
→ backend verifies with Google API
→ backend updates subscription status
→ app fetches subscription state

2️⃣ Capability-Based Feature Gating (Frontend)

Replace isPro checks with capability model.

Model
class Capabilities {
  final bool fullTokenList;
  final bool autoRefresh;
  final bool futureAxis;
  final bool macroExtended;
  final bool retailBehavior;
  final bool marketPulse;
  final bool tokenDiagnostics;
  final bool socialFeed;
  final bool notificationsFull;
}
Mapping
TRIAL / ACTIVE / GRACE → all true
FREE → restricted set

3️⃣ Feature Split

### Free Tier
first 15 tokens
no hi-res mode
no auto refresh
sorting: gainers / losers / volume
detail view:
candles, RSI, ATR, EMA, volume
no future x-axis
macro events:
only in events tab
limited (3 future / 3 past)
bubble maps:
volume only
Fear & Greed index
notifications:
news only

### Pro Tier (Trial + Active)
~150 tokens
all settings & sorting
auto refresh
detail view with future x-axis
macro events:
2 days ahead / 1 day back
retail behavior engine
market pulse page
token diagnostics:
setup quality
crowding
state age
social feed
full notification system

4️⃣ UI / UX Rules
### Feature access

exception: entry points in menu (see below)
Entry points (visible but gated)

These remain visible:

social feed
advanced sorting / diagnostics (sparkline screen)

Behavior:

### Paywall visibility
no aggressive banners
single menu entry: “Get Pro”
after trial expiry:
→ highlight (green CTA)
CTA states

5️⃣ Push Notification Gating
Backend logic

Send notification if:

(type == news AND user enabled news)

OR

(user is TRIAL/ACTIVE/GRACE AND user enabled that category)
Categories
social
macro
market

news

Free users
