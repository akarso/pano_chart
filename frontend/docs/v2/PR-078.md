## PR-078: fix(frontend): billing/trial hardening + gating consistency
🎯 Objective

Close the gaps found in the pro/trial gating sweep. None of these are exploitable today (every
current call site happens to pass the right value), but they're the kind of fail-open default
that turns into a real leak the next time someone adds a call site without noticing the pattern.

🧱 Scope

Frontend only (Dart/Flutter):
- `lib/features/notifications/notification_settings_page.dart` — fail-closed default
- `lib/bootstrap/main.dart` + `lib/features/billing/capabilities.dart` — fail-closed default
  for deep links when billing is unavailable
- `lib/features/billing/billing_manager.dart` — test coverage for the purchase flow
- `pubspec.yaml` — dependency hygiene

1️⃣ Fail-closed default on notification settings
```dart
// notification_settings_page.dart — before
this.isPro = true,

// after
this.isPro = false,
```
Every current call site (`overview_widget.dart:1140` — `caps.notificationsFull`) already
passes an explicit value, so this is a no-behavior-change safety fix, not a functional one.

2️⃣ Fail-closed deep links when billing is unavailable
```dart
// lib/bootstrap/main.dart — before
isProUser: billingManager?.hasFullAccess ?? true,

// after
isProUser: billingManager?.hasFullAccess ?? false,
```
```dart
// lib/features/billing/capabilities.dart — Capabilities.fromBilling — before
if (billing == null) return Capabilities.pro();

// after
if (billing == null) return Capabilities.free();
```
Currently dead code (billing is Android-only, no `ios/` directory exists in the repo yet), but
this is exactly the kind of default that silently unlocks everything for free the day iOS
support is added before billing is wired up there. Fix now while it's free (no behavior change
today), not later under time pressure.

3️⃣ Billing purchase-flow tests
`billing_manager.dart` has no dedicated test file — `purchase()`, `_onPurchaseUpdated`, and
`_verifyAndComplete` (the actual money-path orchestration) are untested today. Add:
- `TestPurchase_Success_UnlocksAfterServerVerification` — purchase completes only after
  `_verifyAndComplete` confirms server-side, not optimistically on the client purchase event
- `TestPurchase_ServerVerificationFails_DoesNotUnlock`
- `TestPurchase_Pending_ShowsPendingState`
- `TestPurchase_Canceled_ReturnsToFreeState`
- `TestRestorePurchases_ReappliesServerVerifiedState`

Use the existing `trial_manager_test.dart` / `http_subscription_api_test.dart` as the pattern
reference for mocking the HTTP layer.

4️⃣ Dependency hygiene
```yaml
# pubspec.yaml — before
environment:
  sdk: '>=2.18.0 <3.0.0'

# after
environment:
  sdk: '>=3.0.0 <4.0.0'
```
Bump after confirming no Dart-2-only syntax remains and `flutter pub get` / CI passes clean.
Separately, migrate off `flutter_markdown` (deprecated by the Flutter team) to the community
fork (`flutter_markdown_plus` or current recommended replacement — check pub.dev for the
currently-endorsed successor at implementation time) in `news_article_screen.dart` — small,
isolated change, low risk.

👉 Not included in this PR (tracked separately, needs product discussion): the 14-day trial is
entirely client-side (`SharedPreferences` install date vs device clock), trivially reset by
reinstall or clock manipulation. Fixing this properly needs either a server-anchored trial
start (tie to the device identity from backend PR-070 — note reinstall still mints a fresh
device identity today, so this alone doesn't fully close it either) or Play Integrity API
attestation. Worth a dedicated PR once PR-070 ships and the team decides how much trial-abuse
resistance is actually worth building for the current user volume.

🚀 Result

- No fail-open defaults left in the pro-gating surface — every "billing unknown" path now
  defaults to free, not pro.
- The one code path that actually moves money has test coverage.
