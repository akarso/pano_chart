## PR-032 UI bugs

- percentages in various places seem incoherent: in a overview page there is often green sparkline yet red value of -0.2% for example. This value must be coherent with timeframe. So calculate it for each timeframe, not for '1 day before' for example

- by 'calculate for timeframe' I don't mean 'calculate for last 15m' when on 15m chart. We fetch 110 candles, so this is 110 * 15 time, this applies also for other timeframes

- for detail view, this is even more complicated, because we open it in the timespan inherited from the overview chart, but we have preceding ~500 candles now too. Proposed solution: put TWO percentage values instead of one, like this: '+24% (?) | -0.4% (?)' - in this example, first percentage - from the last 24h, with the font like there is now, small grey question mark icon, divider, second percentage - from the timespan inherited from overview chart, 2px smaller font, second grey question mark icon. After tap, first help icon resolves to 'last 24h' and second 'reference area (green/red line on time axis)'. Add green line just above x axis - it must start and end where the reference points from the overview chart would be (if I understand correctly - between newest candle and 110 candles back)

- this brings me to my next point. When I open detail view, I want it to be 'reflection' of the sparkliine chart I came from. Same timeframe. Same candles count visible (110). Same ratio (so you have to scale down vertically). Rightmost candle at the edge of the chart area, -110 candle at the left edge of it. Green line over x axis in this area (scalable as the rest of the chart). Only after that, user can pan left or right, zoom in or out. Initially this must mimic sparkline chart he came from.

- when I enter from the bubble map, timespan must be in accordance to the timespan chosen on bubble map. So if user looks at 15m bubble map and chooses some token, initial timespan on this detail token view must be also 15m and also percentage must be correct

- in the detail view add reload icon, and this has to actually refresh chart if user chooses to do so

- when switching timespans on bubble map there is no loader present. It looks like nothing happens and then another bubble map appears. Add preloader.
