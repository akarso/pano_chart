# PR-028 — Parallel Rankings Execution (Worker Pool + Rate Safety)

## Goal

Eliminate sequential bottleneck in rankings computation by introducing bounded concurrency for:

* Candle fetching
* Symbol scoring

Target improvement:

From ~15s worst-case latency → ~1–2s cold computation.

No API contract changes.
No ranking logic changes.
Pure performance refactor.

---

# Problem Summary

Current implementation:

* 153 symbols
* Sequential HTTP call to Binance per symbol
* Sequential scoring loop

Total latency ≈ symbols × API latency.

With ~100ms per call:

```
153 × 100ms ≈ 15 seconds
```

Redis cache only helps after first request.
Cold path is unacceptable.

---

# Design Principles

* Use bounded concurrency (NOT unbounded goroutines)
* Combine fetch + score inside same worker
* Preserve deterministic final sorting
* Respect Binance rate limits
* Keep architecture readable

---

This can be done safely in ONE PR (PR-016).

# Implementation Strategy

## Use errgroup + semaphore (Preferred)

Why:

* Clean cancellation handling
* Error propagation
* Controlled parallelism

---

# Core Pattern

```go
import (
    "golang.org/x/sync/errgroup"
    "golang.org/x/sync/semaphore"
)
```

Inside ranking service:

```go
func (r *DefaultRankSymbols) Rank(ctx context.Context, symbols []string) ([]RankedSymbol, error) {

    workerLimit := int64(12) // configurable
    sem := semaphore.NewWeighted(workerLimit)
    g, ctx := errgroup.WithContext(ctx)

    results := make([]RankedSymbol, len(symbols))

    for i, symbol := range symbols {
        i := i
        symbol := symbol

        if err := sem.Acquire(ctx, 1); err != nil {
            return nil, err
        }

        g.Go(func() error {
            defer sem.Release(1)

            candles, err := r.candleRepo.Fetch(ctx, symbol)
            if err != nil {
                return err
            }

            ranked := r.score(symbol, candles)
            results[i] = ranked
            return nil
        })
    }

    if err := g.Wait(); err != nil {
        return nil, err
    }

    sort.Slice(results, func(i, j int) bool {
        return results[i].Score > results[j].Score
    })

    return results, nil
}
```

---

# Why This Pattern

* semaphore limits active workers
* errgroup propagates first error
* ctx cancellation works properly
* results written safely by index (no mutex needed)

---

# Worker Count

Start with:

```
workerLimit = 8–16
```

Make configurable via env:

```
RANKING_WORKERS=12
```

Too high → Binance throttling.
Too low → wasted CPU.

---

# HTTP Client Requirements

Ensure:

* Shared http.Client
* KeepAlive enabled
* Timeout configured

Example:

```go
Transport: &http.Transport{
    MaxIdleConns:        100,
    MaxIdleConnsPerHost: 20,
    IdleConnTimeout:     90 * time.Second,
}
```

Without this, concurrency gains are reduced.
