# PR-043: Fix FilterNew dedup — timestamp fallback

## Problem

`FilterNew()` iterates posts looking for `LastSeenPostID`. If the ID has
rotated off the RSS feed (high-volume accounts like @elonmusk), the loop
never breaks and ALL posts are returned as "new". This causes a burst of
duplicate push notifications.

## Root Cause

```go
for _, p := range posts {
    if p.ID == account.LastSeenPostID { break }
    result = append(result, p)
}
// If ID not found → result == all posts
```

## Solution

1. Add `LastSeenTimestamp int64` to `domain.Account`.
2. When `LastSeenPostID` is not found in the fetched posts but
   `LastSeenTimestamp > 0`, fall back to timestamp comparison: only
   include posts whose `Timestamp > LastSeenTimestamp`.
3. Update `Watcher.pollNext()` to persist `LastSeenTimestamp` alongside
   `LastSeenPostID`.
4. Migrate SQLite `social_accounts` table to add the column.

## Files Changed

| `domain/social/account.go` | Add `LastSeenTimestamp` field |
