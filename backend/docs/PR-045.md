# PR-045: Server-side push notification filtering

## Problem

`PushConsumer` sends push notifications for ALL new posts without applying
per-user filter settings (omitRetweets, omitReplies, minLength, keywords).
These settings are only stored client-side and applied to the REST feed
endpoint, not to the push pipeline.

This means:
- A single emoji tweet bypasses `minLength`
- Retweets/replies are sent even when the user disabled them

## Solution

1. Add `FilterConfigForAccount` and `SetFilterConfig` to `SubscriptionStore`
   so per-user per-account filter settings are persisted server-side.
2. Modify `PushConsumer.handleBatch()` to load per-user filters and apply
   `applyFilter()` before sending notifications.
3. Add HTTP endpoint `PUT /api/social/subscribe/settings` for the frontend
   to sync filter settings to the server.
4. Update frontend to POST settings when saved in `_AccountSettingsSheet`.
