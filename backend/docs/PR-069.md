# PR-069 — Unified Market Regime Service

## Problem

The backend had **two parallel market classification systems** producing inconsistent results:

| System | Regimes | Features | Consumers |
|---|---|---|---|
| `MarketStateService.Calculate()` | sideways, compression, breakout, trend, silent, indecisive | Health dampening, indecisive guard, silent override | Notifications, SetupService, `/api/market/state` |
| `MetricsService.CalculateRegime()` | sideways, compression, trend, expansion | Softmax scoring, volatility expansion, dispersion | `/api/market/regime`, TransitionService, RegimeHistory |

**Symptom**: A notification said "sideways 88% (1h)" while the app showed "expansion 74% prevalence" on the 1h composite chart — because each system classified the same market differently.

## Solution

Merge the best features from both systems into `MetricsService.CalculateRegime()` as the **single source of truth**. Route all consumers through it.

### What was backported from MarketStateService → MetricsService

1. **Health dampening**: Fetches evaluation snapshots, computes per-token trend health via `ComputeTrendHealth`, dampens trend breadth via `DampenTrendByHealth` when health is poor.
2. **Indecisive guard**: Overrides regime to `indecisive` when dominant softmax score < 50% or gap between top two regimes < 20pp.
3. **Silent override**: When regime is sideways/indecisive AND average absolute return < 0.5% AND volume ≤ median × 1.5 → regime becomes `silent`.
4. **Label computation**: Uses `BuildMarketLabel` to produce human-readable health labels ("Strong", "Weakening", etc.).

### What MetricsService already had (kept)

- Softmax regime scoring (temperature=4)
- Volatility expansion metric
- Dispersion metric
- Expansion regime (breakout activity + elevated volatility)

## Changes

### Domain (`domain/market/regime.go`)
- Added `RegimeIndecisive` and `RegimeSilent` regime constants
- Added `EffectiveTrend`, `BreakdownRate`, `Label` fields to `RegimeSummary`

### Regime Detector (`application/market/metrics/regime_detector.go`)
- Extracted `dominantRegime()` helper from `detectRegime()`
- Added `applyIndecisiveGuard(regime, scores)` — indecisive when dominant < 50% or gap < 20pp
- Added `topTwoFloats()` helper

### MetricsService (`application/market/metrics/metrics_service.go`)
- Added health dampening block: fetches evals → computes trend health → dampens breadth
- Added indecisive guard after regime detection
- Added silent override (sideways/indecisive + low returns + normal volume)
- Added label computation via `BuildMarketLabel`
- Populates `EffectiveTrend`, `BreakdownRate`, `Label` in the returned summary

### MarketStateService (`application/market/market_state_service.go`)
- Exported `AggregateActivityMetrics()` (was lowercase) for use by MetricsService

### Notification Scheduler (`application/notifications/scheduler.go`)
- `MarketProvider` interface: `Calculate(timeframe) → Summary` changed to `CalculateRegime(ctx, timeframe) → RegimeSummary`
- `checkMarketState()`: Uses `RegimeSummary` fields, logs regime scores, handles `RegimeExpansion`
- `checkMarketForUser()`: Uses `Scores.Trend/Expansion/Sideways` directly (softmax scores already normalised)
- Removed `normalizeBreadth()` — no longer needed

### SetupService (`application/setups/service.go`)
- `MarketProvider` interface: same change as scheduler
- `Evaluate()` calls `CalculateRegime(ctx, timeframe)`, reads `EffectiveTrend`

### Server Wiring (`cmd/api/main.go`)
- `setupService.SetMarketProvider(metricsService)` (was `marketService`)
- Notification scheduler wired with `metricsService` (was `marketService`)

### Regime Handler (`adapters/http/market_regime_handler.go`)
- `regimeResponse` DTO now includes `effective_trend`, `breakdown_rate`, `label` fields

### Frontend — Regime Data (`lib/features/market_state/regime_data.dart`)
- Added `effectiveTrend`, `breakdownRate`, `label` fields with JSON parsing

### Frontend — Market Pulse Screen (`lib/features/market_state/market_pulse_screen.dart`)
- Regime card shows health label suffix (icon + coloured text) when label is non-empty

### Tests
- `scheduler_test.go`: `fakeMarketProvider` → `CalculateRegime` returning `RegimeSummary`; all market test data uses `RegimeScores` instead of `Breadth`
- `config_test.go`: Same migration for per-user config tests and multi-timeframe tests
- `regime_test.go`: Updated sideways/no-symbols tests to expect `indecisive` (no clear signal → honest about lack of confidence)

## Backward Compatibility

- `/api/market/state` endpoint **still works** — `MarketStateService.Calculate()` is untouched. It remains available for any legacy consumers but is no longer the primary source of truth.
- `/api/market/regime` is the authoritative endpoint. The response now includes three additional fields (`effective_trend`, `breakdown_rate`, `label`).

## Migration Path

1. This PR: all internal consumers (notifications, setups) route through `MetricsService`
2. Future: deprecate `/api/market/state` endpoint once no external consumers depend on it
