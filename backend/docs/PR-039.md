# PR-039: Financial Events Feed Integration (FinanceFlow API)

## 1. Objective

Integrate macroeconomic event feed using FinanceFlow API and expose a normalized, cached endpoint for mobile clients.

Scope:

* Fetch economic calendar data from FinanceFlow
* Normalize response format
* Cache results server-side
* Expose simplified `/events` endpoint to app
* Support UTC + local time conversion client-side

Non-goals (v1):

* No scoring impact
* No sentiment analysis
* No filtering by consensus/actual
* No historical backfill beyond date range request

---

## 2. External API

### Provider

FinanceFlow API

### Endpoint

GET https://financeflowapi.com/api/v1/financial-calendar

### Parameters

* api_key (required)
* country (optional)
* date_from (YYYY-MM-DD)
* date_to (YYYY-MM-DD)

Example:

GET https://financeflowapi.com/api/v1/financial-calendar?api_key=XXX&country=United States&date_from=2025-03-01&date_to=2025-03-07

## 4. Data Model

### 4.1 External Response (partial)

```go
type financeFlowResponse struct {
    Success bool   `json:"success"`
    Code    int    `json:"code"`
    Message string `json:"message"`
    Data    []struct {
        Country         string `json:"country"`
        ReportName      string `json:"report_name"`
        Actual          string `json:"actual"`
        Previous        string `json:"previous"`
        Consensus       string `json:"consensus"`
        EconomicImpact  string `json:"economicImpact"`
        ReportDate      string `json:"report_date"`
        Datetime        string `json:"datetime"`
    } `json:"data"`
}
```

---

### 4.2 Internal Normalized Model

```go
type Event struct {
    ID        string    `json:"id"`
    Country   string    `json:"country"`
    Title     string    `json:"title"`
    Impact    string    `json:"impact"`   // high | medium | low
    Timestamp time.Time `json:"timestamp"` // always UTC
}
```

---

## 5. Impact Normalization

Map FinanceFlow values:

* "High" → high
* "Moderate" → medium
* "Low" → low

Unknown → medium (safe default)

---

## 6. Timestamp Handling

FinanceFlow format:
"2025-03-03 14:45:00"

Assumption: UTC (must confirm in docs).

Parsing:

```go
layout := "2006-01-02 15:04:05"
t, err := time.Parse(layout, dto.Datetime)
```

Store internally as UTC.

Mobile client converts to local zone.

## 7. Backend Endpoint

### Route

GET /api/v1/events

### Query Params

* date_from (optional)
* date_to (optional)
* impact (optional: high|medium|low)
* country (optional)

### Example Response

```json
{
  "events": [
    {
      "id": "us-2025-03-03-1445-pmi",
      "country": "United States",
      "title": "S&P Global Manufacturing PMI Final",
      "impact": "medium",
      "timestamp": "2025-03-03T14:45:00Z"
    }
  ]
}
```

## 8. Caching Strategy

### Why

Avoid:

* API rate limits
* Repeated identical requests
* Mobile hammering

### Approach

In-memory cache (v1):

Key:
country + date_from + date_to

TTL:

* 30 minutes (upcoming window)
* 6 hours (past window)

Future upgrade:
Redis if horizontally scaled.

---

## 9. Fetch Strategy

Mobile app will:

* Request events for [today - 1 day] → [today + 7 days]

Backend:

* Fetch once
* Cache
* Serve filtered results

---

## 10. Failure Handling

If FinanceFlow fails:

* Log error
* Return cached data if exists
* If no cache → return empty list (not 500)

Events are non-critical.

---

## 11. Security

* API key stored in backend config (NOT in mobile) (config_yaml -> api_keys)
* Never exposed to client
* All FinanceFlow requests proxied through backend
