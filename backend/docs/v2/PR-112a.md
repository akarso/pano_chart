## PR-112a: Replay mode (backend `asOf`)

**Layer:** application + adapters. **Depends on:** PR-089b.

### Scope

- `application/replay`: `WithAsOf` / `AsOf`, `ParseUnixSeconds`,
  `ValidateAsOf` (no future), `FetchCandles` → historical `GetSeries` then
  filter to bars with `open+tf ≤ asOf` (no forming-bar look-ahead).
- Rankings (`GetRankingsRequest.AsOf`), composite candle provider, Redis
  rankings/composite caches (bypass on asOf), evaluation-store skip on
  replay, regime history `PeriodsEndingBefore`, transition matrix/signal
  skip on replay, market observer skip on replay.
- HTTP: `?asOf=` on rankings / regime / composite / transition / regime
  history. Middleware `RequireReplayAccess` — Pro + Bearer (hard) +
  10/min/user rate limit.
- `COMMON.md` contract for the query param and error codes.

### Out of scope

- Frontend scrubber (PR-112b).
- Persisting replay results or asOf-keyed Redis entries.

### Tests

- `FetchCandles` live vs asOf; forming bar excluded at mid-bar `asOf`.
- Badge emit skipped under asOf; transition age/horizon + emit under asOf.
- Rankings: asOf early-uptrend window vs live late-downtrend scores.
- Redis rankings cache bypass when `AsOf` set.
- Regime history point-in-time view + `AgeAtAsOf` for transition horizon
  (over-fetch `max(limit×3, limit+10)`; deep asOf may miss covering period —
  documented). Replay transition age never falls back to live default `12`.
- Badge / transition signal emit skipped under replay; MTF overlay skipped.
- Handler invalid asOf / asOf forwarded to use case.
- Middleware: passthrough without asOf; 401/403/429/inject for asOf.
