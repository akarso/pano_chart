## PR-109: Learned regime classifier (offline first)

**Layer:** tooling + domain. **Depends on:** PR-090–092 (≥ 4 weeks of
outcomes), PR-088.

### Scope

- `cmd/export_dataset`: CSV of **resolved setup** signals (default
  `-kind setup`). Skips `ExcludedFromHitRate` outcomes and rows missing
  `regime_code` / feature keys (pre-PR-109). Uses `Filter{Limit: -1,
  OldestFirst: true}`. `-max-rows N` caps **eligible written** rows (DB load
  stays uncapped so excluded/incomplete rows do not consume the budget).
  `regime_label` is the four-way raw-score argmax at emission (includes
  **expansion** via strict win; all-zero → sideways); `success` is the
  separate outcome grade. Label/features do not depend on
  `scoring.regime_model`.
- File load / path discovery for `regime_model.yaml` lives in
  `infrastructure/scoring`; domain owns parse/validate/infer only.
- Setup signal `ATR`: TrueATR(14) when available, else SimpleATR so short
  series still grade. Feature `atr_pct` uses TrueATR only (0 when too short).
- Advertised export features are `trend…atr_pct` (no constant-zero rs/alignment).
- Training stays out of repo. Ship **`classes`** (one-vs-rest logistic heads
  for trend/sideways/compression/expansion). Binary `weights`/`bias` are for
  setup-success notebooks only and are **not** used by `ClassifyStructure`.
- `domain/scoring/logistic.go`: `Predict`, `ClassifyStructure`,
  `ParseRegimeModelYAML`, `ValidateForInference` (requires all four classes
  with non-empty known-feature weights; rejects placeholder / non-finite
  coeffs), `EfficiencyRatio`, `BuildRegimeFeatures`, `ClosesFromCandles`.
- Shipped `config/regime_model.yaml` has `placeholder: true` so
  `ClassifyStructure` refuses and `ValidateForInference` fails — flipping
  `scoring.regime_model: learned` without a real model **fails startup**.
- `ScoreMarketTape`: when a non-placeholder model is installed, model
  probabilities become `Structure`; **PR-115 State rules still apply**
  (`tapeTrendGate`, indecisive margins). Bias / health stay heuristic.
- Setup path: shared `setupRegimeFeatures` (raw scores + Wilder
  `TrueATR(14)`) used by both `emitSetupSignal` and `dominantRegimeLearned`.
  Setup signal `ATR` is the same TrueATR so CSV `atr`/`price` agree with
  `atr_pct`. Expansion folds to sideways for setup labels.
- Flag `scoring.regime_model: heuristic|learned` (default **heuristic**).
  Invalid values fail startup. Never ship `learned` as default without a
  scorecard A/B ≥ +5pp hit rate.

### Out of scope

- In-repo training / notebooks.
- Historical EvaluationSnapshot join (features captured on the signal at
  emission into `Context`).
- Streaming/cursor export (use `-max-rows` until DB growth requires it).
- Using one shared feature vector across **tape** (`TapeTrend`) and
  **setup** (`Trend Predictability`) — train separate models or accept
  that tape vs symbol heads need matching feature sources.

### Tests

- `Predict` sigmoid; placeholder / incomplete classes → ok=false.
- Stub YAML is placeholder and fails `ValidateForInference`.
- `ValidateRegimeModelMode` rejects typos.
- `ScoreMarketTape` keeps PR-115 trend gate when learned structure favors
  compression; placeholder keeps heuristic.
- `classifyTapeLearned` with TapeTrend &lt; 0.5 → indecisive (flat masses) or
  compression (dominant mass).
- `dominantRegimeLearned` compression / expansion→sideways / trend→direction.
- Emit ATR matches feature `atr_pct`; Query `Limit: -1` + `OldestFirst`.
