## PR-052 - staggered polling

- first of all, we now need to pull all ~150 symbols at application load. There are too many pain points resulting from lazy loading in batches. So this may be still loaded in batches (but immediately one after another), or full 150 list at once. This is question of "faster partial load but 3x queries vs a bit slower but in one query" - assess the impact on UI and backend load and choose better option

- there will be gating, because app will start as pro trial, then default to free version after 14 days and pro will be available as subscription. So take this into account: auto refresh will be available only for pro version

- preview list must be refreshed automatically. To minimize the impact, I want to use a UI trick: right now we have glowing points at the end of sparklines after manual refresh. This stays as an option for free tier, but for pro it must be activated sequentially with 20ms delay between symbols (sparklines). This will result in 20ms x 150 base delay between requests for next data. Add to this 5s margin: (20ms x 150 ) + 5000ms. Put 20ms and 5000ms somewhere in a var or const easy to config, not hardcoded.

- this 'glowing point' trick should run over the whole 150 symbols. Again, there were too many issues with trying to implement this using intersection observer and only visible window.

- macro events api stays mostly as is, for now - called whenever needed, not auto refreshed. Exception: when user stays on a detail chart for longer than 15m, call an update. So some 15m counter will be nedeed for that, resets with detail chart close

- detail view has to be auto refreshed (for pro) also. 1m - every 10s, 5m -> every 1m, 15m -> every 3m, 1h -> every 10m, 4h -> every 15m, 1d -> every 1h. Everything has to be recalculated after refresh. time axis gets longer, macro events keep getting closer to the 'current' time, new events appear if their 15m refresh was triggered, last candle is being appropriately redrawn.

- bubble map has to be auto refreshed (for pro) also. 1m - every 10s, 5m -> every 1m, 15m -> every 3m, 1h -> every 10m, 4h -> every 15m, 1d -> every 1h. Everything has to be recalculated after refresh. Volume, color, price change, bubble size.

- for pro version 'stale data' warning should be unused. I think there is separate one for 'no connection' and this stays in both tiers.
