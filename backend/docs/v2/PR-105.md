## PR-105: Percentile-normalized compression

**Layer:** domain + application. **Depends on:** PR-094 (telemetry optional).

### Objective

Absolute compression divisors (`MaxExpectedATRDrop: 0.005` etc.) cannot fit every
symbol/timeframe. Score tightness against the symbol's own history instead.

### Scope

- `CompressionPercentileScoreCalculator` (`Name` = `"Compression Pct"`):
  - Window hint **500** bars (`WindowHint()`).
  - If fewer than **200** bars → fall back to legacy `CompressionScoreCalculator`.
  - Per bar: `bw_i` = 20-bar range width / close; `atr_i` = 14-bar rolling ATR.
  - `P_bw` / `P_atr` = empirical percentile ranks of the last bar (0 = tightest).
  - `SqueezeDuration` = consecutive trailing bars with `bw < 20th` percentile,
    capped at 20, normalized `/20`.
  - Score `= (1−P_bw)×0.5 + (1−P_atr)×0.3 + SqueezeDuration×0.2`.
- Optional `WindowHintProvider` + `MaxWindowHint(floor, calcs…)` so rankings
  fetch `max(precision, hints)` without changing the default 110-bar path.
- Config / env: `scoring.compression_algo: absolute|percentile` (default
  **absolute**). Env override `COMPRESSION_ALGO`.
- `GetRankings` uses the selected calculator; Scores key stays `"Compression"`.
- Redis rankings cache keys include `compression_algo` (with trend_algo) so
  flips cannot serve stale totals.

### Out of scope

- Flipping production default to percentile.
- Changing Market Pulse / tape compression (stays absolute).
- Changing breakout detector internals beyond consuming the selected score.

### Tests

- WindowHint = 500; MaxWindowHint elevates fetch size when percentile is present.
- Short series (<200) matches legacy absolute score.
- Synthetic 500-bar series with last-20 half-range → score ≥ 0.7.
- Uniform noise → score ≈ 0.5 ± 0.15.
- ParseCompressionAlgo empty/absolute/percentile/invalid.
