## PR-087: fix(scoring): per-timeframe Sideways config via TimeframeAwareCalculator

🎯 Objective

`cmd/api/main.go` built `SidewaysV5ScoreCalculator{Config:
NewSidewaysV5ConfigForTimeframe("1h")}` once and reused it for every timeframe.
`IdealATRRange` is timeframe-specific (`15m` ≠ `1d`), so non-1h rankings were
mis-scored. Wrap the calculator so each series timeframe gets its own config.

See ROADMAP Track A — PR-087.

🧱 Scope

- `domain/scoring/timeframe_aware_calculator.go` — new wrapper
- `cmd/api/main.go` — Sideways V3/V5 wired through the wrapper
- Tests under `tests/domain/scoring/`

Out of scope: Compression / Breakout (no per-timeframe config in `config.go`),
tape_regime (already calls `NewSidewaysV5ConfigForTimeframe(timeframe)`).

1️⃣ TimeframeAwareCalculator

```go
type TimeframeAwareCalculator struct {
    Name_   string
    Factory func(tf string) SymbolScoreCalculator
    cache   sync.Map // tf → SymbolScoreCalculator
}
```

`Score` uses `series.Timeframe().String()` to LoadOrStore the inner calculator.

2️⃣ main.go wiring

V5 (default) and V3 are built via `SidewaysCalcFor` (TimeframeAwareCalculator).
For V5/default, `main.go` wraps the completed calculator once with
`LoggingScoreCalculator` **outside** TimeframeAware so a single decorator
samples scores across all timeframes under the public name
`"Sideways Consistency"`.

3️⃣ Compression / Breakout

Checked `config.go`: neither has per-timeframe maps. Left unchanged.

✅ Definition of Done

- [x] Same candle shape at `15m` vs `1d` yields different SidewaysV5 scores
- [x] Two scores on the same timeframe are identical; Factory called once (cache)
- [x] No hardcoded `"1h"` in `main.go` for score calculators
- [x] gofmt / go vet / go test clean for touched packages

🚀 Result

Rankings / overview / symbol detail score Sideways with the IdealATRRange that
matches the requested timeframe.

📝 Implementation notes

- SidewaysV5.Score already re-resolved IdealATRRange from IdealATRRangeMap when
  present; the wrapper still matters so V3 (and any future TF-specific fields)
  bake config at construction. Override path (`SidewaysCalcFor` / `sidewaysCalcFor`)
  shares the same factory as `main.go`.
- Remaining `"1h"` strings in `main.go` are regime-history backfill TFs, not
  calculator wiring.
- CR follow-up: empty tapes are not Redis-cached; V3 differ-by-TF test added.
