## PR-094: feat(scoring): score distribution telemetry store

🎯 Objective

Persist sampled calculator scores so Track E can compute percentiles. Logs stay
the fallback when the sample database cannot open.

See ROADMAP Track B — PR-094.

🧱 Scope

- `application/ports/score_sample_sink.go` — `Record` and `Scores`
- `infrastructure/scoring/sqlite_sample_sink.go` — `score_samples`, indexes
  `(calculator, tf, at)` and `(at)`, queued writes, retention delete on the
  retention loop (immediate, then daily)
- `infrastructure/scoring/logging_score_calculator.go` — `SetSink`; env sample rate
- `application/scoring/percentiles.go` — empirical CDF and p5..p95
- `adapters/http/score_distribution_handler.go` — debug GET
- `cmd/api/main.go` — dedicated DB, retention loop, route behind `PC_DEBUG_ENDPOINTS=1`
- `domain.CandleSeries.Symbol()`
- `COMMON.md` — debug endpoint

Out of scope: Track E percentile UI; changing which calculators are wrapped
(still Sideways V5 only).

1️⃣ Store

`PC_SCORE_SAMPLE_DB` defaults to `./score_samples.sqlite` (not the signal DB).
Timestamps are UTC unix nanoseconds. `Scores` returns the most recent 100000
rows inside the retention window, so a missed daily purge cannot feed
percentiles and one debug request cannot load the whole table. The read
finishes before those scores are sorted in memory.

`Record` enqueues on a bounded channel and a background writer batches inserts.
A full queue drops the sample. `Score` does not wait on disk.

`PC_SCORE_SAMPLE_RATE` defaults to `0.1` (previously a hardcoded `0.05`).
Empty, non-finite (`NaN`, `Inf`), and otherwise invalid values use `0.1`.
The constructor clamps a finite rate to `[0, 1]` and treats a non-finite rate
as `0`. `SetSink` is atomic; `nil` restores logging. When a sink is set, a
sampled score is recorded and not logged. A record error is logged and does
not fail `Score`.

`PC_SCORE_SAMPLE_RETENTION` defaults to 90 days (`90d` or a Go duration).
`RunRetention` deletes expired rows once at start, then about once a day with
up to 15 minutes of extra delay. Opening the database does not purge.
`Close` waits up to 2 seconds for the writer, then returns so shutdown can
finish if disk I/O is stuck. A constraint error skips that row only while the
transaction is still open. Disk, full, corrupt, and transaction-rollback
errors abort the batch. Skip/abort logs are limited to one line per second.
Calculator names are the distinct calculators that still have retained rows.
A commit or purge drops that cache. A failed load is reused for one second,
then retried. The load uses the caller's context and stops after 3 seconds.
`Flush` returns the writer error when a batch was not committed.

2️⃣ Query

`Percentile` is `count(samples <= score) / n`. Empty → `ErrNoSamples`.
`Distribution` is nearest-rank at 5, 10, … 95 (`ceil(p/100*n) - 1`, clamped).

3️⃣ Endpoint

`GET /api/debug/score-distribution?calculator=&timeframe=` is registered only
when `PC_DEBUG_ENDPOINTS=1` and the sink opened. It listens on `PC_DEBUG_ADDR`
(default `127.0.0.1:8082`), a loopback socket that is not the public API.
Non-loopback bind addresses are refused. JSON
`{calculator, timeframe, distribution}`. Missing params `400`, other methods
`405`, known calculator with no rows for that timeframe `404`, unknown
calculator `400` plus the retained names. Known means any retained sample for
that name, on any timeframe.

🚀 Result

Sideways V5 samples accumulate for 90 days. With `PC_DEBUG_ENDPOINTS=1`, curl
returns the p5..p95 curve for a calculator and timeframe.

📝 Implementation notes

- Sample rate moved from hardcoded `0.05` to `PC_SCORE_SAMPLE_RATE` default `0.1`.
- Retention runs on the process background context and stops on shutdown, before the DB is closed.
- The handler does not read `PC_DEBUG_ENDPOINTS`; `main` decides whether to register it.
