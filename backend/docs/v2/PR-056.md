# PR-056 — Trend Direction & Overview Sorting Fix

## Problem

The Overview/Rankings screen had several issues with directional sorting:

1. **Trend "Up" showed downtrending tokens** — the backend sorts by absolute
   score (step 5 of the pipeline), then signs trends (step 8, `signAdjustTrend`).
   The frontend only loaded 30 items per page and sorted locally, so page 1
   could contain mostly downtrends.
2. **Scroll caused results to shift/reorder** — pagination loaded 30 items at a
   time; local sort re-ran on each page load, shuffling visible items.
3. **Badges were direction-agnostic** — a "TREND" badge appeared identically on
   uptrend and downtrend tokens (always blue).
4. **Compression and breakout had no direction support** — the frontend used
   `totalScore` as a placeholder for these sorts.

## Solution

### Pagination — load all tokens in one request

| File | Change |
|------|--------|
| `frontend/…/get_rankings_impl.dart` | `pageSize` raised from 30 → **200** |
| `backend/adapters/http/rankings_v2_handler.go` | pageSize cap raised from 100 → **200** |

With ~150 tokens in the universe, a single request now returns all items.
No scroll-triggered `loadNext` needed for typical usage.

### Direction-aware sorting (`_sortItems`)

| Sort | Up (↑) | Down (↓) |
|------|--------|----------|
| `trend` | Descending by signed `trendScore` (strongest uptrend first) | Ascending (most negative first) |
| `compression` | Descending by signed compression score (positive = sparkline slopes up) | Ascending (sparkline slopes down) |
| `breakout` | Descending by `breakoutUpScore` | Descending by `breakoutDownScore` |
| `sideways` | By `sidewaysPercentile` (unchanged) | — |
| `gain` / `losers` | Unchanged | — |

Compression direction is derived from sparkline slope:
`s.last >= s.first → +compression` else `−compression`.

Breakout uses separate backend scores (`Breakout Up`, `Breakout Down`) that
were already computed but never parsed by the frontend.

### New score fields

| Layer | File | Change |
|-------|------|--------|
| DTO | `dto/rankings_response_dto.dart` | Added `compression`, `breakoutUp`, `breakoutDown` to `RankingScoresDto` (default 0.0, backward compat). Parsed from backend keys `Compression`, `Breakout Up`, `Breakout Down`. |
| Model | `overview_state.dart` | Added `compressionScore`, `breakoutUpScore`, `breakoutDownScore` to `OverviewItem` (default 0.0). |
| Mapping | `get_rankings_impl.dart` | Maps DTO → model for the 3 new fields. |
| Cache | `overview_view_model.dart` | Serialization/deserialization includes new fields with null-safe fallback. |

### Direction-aware badges

| File | Change |
|------|--------|
| `overview_widget.dart` | `_signalColor(signal, {trendScore})`: trend badge → green if `trendScore ≥ 0`, red if `< 0`. `_signalLabel(signal, {trendScore})`: trend badge → `↑ TREND` or `↓ TREND` (abbreviated `↑T` / `↓T`). `_buildBadge()` passes `item.trendScore` to both functions. |
