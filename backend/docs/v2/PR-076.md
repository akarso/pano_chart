## PR-076: chore(backend): operational hardening
🎯 Objective

A grab-bag of low-risk, high-value cleanup found during the audit — none of these change
business behavior, they fix operational robustness and remove clutter. Bundled into one PR
because each item is small; keep as separate commits within the PR for easy review/revert.

🧱 Scope

Backend only (Go):
- graceful shutdown in `cmd/api/main.go`
- remove startup smoke-test code that blocks boot on live network calls
- tighten CORS now that PR-070 adds real auth
- delete duplicated `topTwo`/`topTwoFloats`
- fix the stale doc comment on `EvaluationProvider`

1️⃣ Graceful shutdown
```go
// cmd/api/main.go — before
log.Fatal(http.ListenAndServe(addr, mux))

// after
srv := &http.Server{Addr: addr, Handler: mux}
go func() {
    if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
        log.Fatalf("server error: %v", err)
    }
}()

sig := make(chan os.Signal, 1)
signal.Notify(sig, os.Interrupt, syscall.SIGTERM)
<-sig
log.Println("[main] shutting down...")

// Track every background goroutine (socialWatcher, pushConsumer, notifyScheduler — each
// already started via `go xyz.Run(socialCtx)`) so shutdown can wait for them to actually
// exit, not just signal them to stop. Add wg.Add(1)/defer wg.Done() to each of those
// goroutines' launch sites alongside this change.
var backgroundWG sync.WaitGroup

shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
if err := srv.Shutdown(shutdownCtx); err != nil {
    log.Printf("[main] graceful HTTP shutdown failed, forcing close: %v", err)
    _ = srv.Close() // deadline hit with requests still in flight — cut them off rather than hang
}

socialCancel() // signal socialWatcher/pushConsumer/notifyScheduler to stop

waitDone := make(chan struct{})
go func() { backgroundWG.Wait(); close(waitDone) }()
select {
case <-waitDone:
case <-time.After(5 * time.Second):
    log.Println("[main] background workers didn't exit in time, closing stores anyway")
}

// Only close what the background workers depend on AFTER they've stopped touching it —
// closing earlier risks a use-after-close panic in a goroutine still mid-iteration.
paymentRepo.Close() // independent of the social/push workers — fine on its own timeline
socialAccountStore.Close()
socialSubStore.Close()
deviceStore.Close()
log.Println("[main] shutdown complete")
```
This ensures the `defer`s that exist today (lines ~290/430/461) actually run, background
goroutines get their context cancelled instead of being abandoned mid-request on container
stop, AND (the part a naive cancel-then-close sequence misses) the stores those goroutines use
aren't closed out from under them while they're still shutting down.

2️⃣ Remove boot-blocking smoke-test code
`cmd/api/main.go:159-192` makes live Binance calls purely to `fmt.Printf` sample output at
startup ("Test universe" / "Test volume provider"), plus a dangling "Test ranker" label with no
code under it. Delete the block entirely — it has no functional purpose and adds a real network
dependency to server boot that has nothing to do with actually serving traffic. If this was
useful during initial development, replace with a `make smoke-test` script or an integration
test, not code that runs on every production boot.
