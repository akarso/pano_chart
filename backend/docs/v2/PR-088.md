## PR-088: test(scoring): golden candle fixtures per regime archetype

🎯 Objective

Pin real-shaped OHLCV snippets (110 bars) for ten regime archetypes so
algorithm changes can be judged against stable expected score *ranges*
instead of sine-wave toys. Blocks Track E.

See ROADMAP Track A — PR-088.

🧱 Scope

- `tests/fixtures/candles/` — 10 JSON fixtures + README + `Load` helper
- `tests/domain/scoring/golden_test.go` — per-archetype calculator ranges
- `tests/application/market/golden_tape_test.go` — up + down tape guards
- `application/market/health.go` — direction-aware adverse-move penalty (so
  clean downtrends are not dampened into sideways on the tape)

Out of scope: live Binance fetch scripts (must not be committed); Track E
range tightening; calculator algorithm changes beyond the health fix above.

1️⃣ Fixtures

JSON shape: `symbol`, `timeframe`, `archetype`, `source`, `recorded`,
`candles[{t,o,h,l,c,v}]` with exactly 110 bars. Current set is deterministic
`source: synthetic` shaped like each archetype (offline CI). README documents
how to swap in a live Binance window.

2️⃣ Loader

`fixtures.Load(t, name)` rebuilds a `domain.CandleSeries` via
`NewCandleUnsafe` / `NewCandleSeries`.

3️⃣ Golden score ranges

Ranges match **current** Trend / SidewaysV5 / Compression / Breakout /
Gain-Loss behaviour. Track E tightens against these fixtures.

4️⃣ Tape guards

- `ScoreMarketTape(messy_uptrend)` → `Structure.Trend > Sideways`, bias up
- `ScoreMarketTape(clean_downtrend)` → `Structure.Trend > Sideways`, bias down

✅ Definition of Done

- [x] 10 fixtures committed (110 candles each)
- [x] README explains format + regeneration (+ score-vector table)
- [x] `fixtures.Load` helper (`RequiredBars`, archetype check)
- [x] `golden_test.go` ranges pass on current code (incl. Breakout ≥ 0.2)
- [x] Tape goldens: messy_uptrend (PR-084) and clean_downtrend
- [x] Health adverse-move penalty is direction-aware

🚀 Result

Golden fixtures and tests land. Track E can change calculators against pinned
archetypes without inventing new toys each PR.

📝 Implementation notes

- Messy uptrend uses mid-window chop that damps out so the finish sits near
  the highs — otherwise `ComputeTrendHealth` dampens Trend into Sideways and
  the PR-084 guard fails even when raw Trend Predictability is high.
- `ComputeTrendHealth` adverse-move penalty is **direction-aware**: large
  negative window return no longer collapses healthy downtrends (PR-088 CR).
  Tape golden covers `clean_downtrend` symmetrically.
- Breakout fixture is a swing channel + piercing last bar with volume (same
  shape as domain breakout unit tests), not a drift ramp — so Breakout ≥ 0.2
  is enforceable. `failed_breakout` pins Breakout ≈ 0 after re-entry.
- README includes a measured score-vector table (intent vs what code sees).
