## PR-114: fix(events): backoff on FinanceFlow errors (stop 1/min retry storm)

🎯 Objective

FinanceFlow usage is usually ~50 calls/day (healthy: notification scheduler every
1 minute absorbed by a 30‑minute in-memory cache). On some days it jumps to
~1440 (= 1/min for 24h) and stays there. Root cause: after the normal TTL
expires, a failing upstream still gets called every scheduler tick because the
stale-cache fallback returned data **without** extending freshness — so the
next minute is another miss → another billed call → forever until process
restart or upstream recovery.

See ROADMAP “Hotfixes” — PR-114. Independent of the killer-app tracks; land ASAP.

🧱 Scope

Backend only:
- `application/usecases/get_events.go` — error hold / empty hold
- `application/usecases/get_events_backoff_test.go` — regression tests

Out of scope: Redis events cache, changing `MacroCheckInterval`, frontend.

1️⃣ Behaviour

On `FetchEvents` error:
- If a stale entry exists → set `errorHoldUntil = now + 15m`, serve stale.
- If no entry → cache empty list with the same 15m hold.
- While `now < errorHoldUntil`, `getCached` returns the entry (soft hit) → **no**
  FinanceFlow call.
- On a later successful fetch → normal `putCache` clears the hold.

2️⃣ Verification

- `TestGetEvents_ProviderError_ExpiredTTL_BacksOff` — seed, expire, fail once,
  five more Executes → still 2 provider calls total.
- `TestGetEvents_ProviderError_NoCache_BacksOffEmpty` — cold fail → 1 call, then
  suppressed.
- Existing `get_events` tests still pass.

✅ Definition of Done

- [x] backoff tests pass
- [x] gofmt / go test for usecases + events tests
- [x] ROADMAP Hotfixes section documents PR-114

🚀 Result

A FinanceFlow blip after TTL expiry costs ~1 call per 15 minutes of downtime,
not ~1 call per minute for the rest of the day. Healthy days stay ~50.

📝 Implementation notes

- Hold duration is 15m (half the upcoming success TTL). Short enough to notice
  recovery; long enough that a multi-hour outage is ~4 calls/hour max for the
  scheduler key, not 60.
- Cache remains process-local (pre-existing). Multi-replica multiplication is
  a separate follow-up (Redis), not this PR.
