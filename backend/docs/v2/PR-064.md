## PR-064: feat(setup): integrate trend health into setup quality scoring
🎯 Objective

Improve setup quality score by incorporating Trend Health, so that:

- strong + healthy setups rank highest
- structurally good but breaking setups get downgraded
- sideways/compression remain unaffected
🧠 Design Principle
setup_quality = structural_score × context_modifier

Where:

context_modifier = trend_health (for trend-based setups)
🧱 Scope
- extend setup scoring model
- apply health only where relevant (trend setups)
- avoid mixing conflicting regimes
- keep architecture clean and modular
1️⃣ Extend Setup Model
File
internal/setups/types.go
Update struct
type SetupScore struct {
    BaseScore     float64 // existing structural score
    FinalScore    float64
    Regime        string  // sideways / compression / uptrend / downtrend
    TrendHealth   float64 // 0–1, only meaningful for trends
}
2️⃣ Context Modifier Logic
File
internal/setups/scoring.go
Core function
func ApplyContextModifier(s SetupScore) SetupScore {

    modifier := 1.0

    switch s.Regime {

    case "uptrend", "downtrend":
        // health-aware scaling
        modifier = trendHealthModifier(s.TrendHealth)

    case "compression":
        // slight boost if market is healthy
        modifier = 1.0

    case "sideways":
        modifier = 1.0
    }

    s.FinalScore = s.BaseScore * modifier

    return s
}
3️⃣ Trend Health Modifier
Function
func trendHealthModifier(health float64) float64 {

    // nonlinear scaling (important)
    // preserves strong setups, kills broken ones

    switch {
    case health > 0.8:
        return 1.05 // slight boost

    case health > 0.6:
        return 1.0

    case health > 0.4:
        return 0.7

    case health > 0.2:
        return 0.4

    default:
        return 0.2
    }
}
Why nonlinear?

Because:

0.9 → 0.8 health = small difference
0.4 → 0.2 health = huge difference (trend breaking)
4️⃣ Integration Point

Where you currently compute setup scores:

score := computeBaseScore(...)
Add:
score.TrendHealth = token.TrendHealth
score = ApplyContextModifier(score)
5️⃣ Important Safeguard (critical)
DO NOT apply health to:
sideways setups
compression setups
Why

You already noted:

sideways + compression are valid independently

Applying health there would:

❌ introduce noise
❌ punish good range setups

6️⃣ Ranking Impact
Before

→ A wins (wrong)
After
Token A: 0.85 × 0.3 = 0.25
Token B: 0.80

→ B wins (correct)
