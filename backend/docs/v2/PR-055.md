# PR-055 — Real Scoring Calculators for Market Pulse Breadth

## Problem

The Market Pulse screen used crude `proxyBreadth()` heuristics for regime
detection while the Overview/Rankings screen used the real `domain/scoring`
calculators (TrendPredictability, SidewaysV5, DetectCompression,
DetectBreakout).  This caused the two screens to disagree on market conditions.

`proxyBreadth` estimated trend breadth as `|return| × 5` and compression
breadth as `1 − ATR-ratio`, with no sideways or breakout signals at all.

## Solution

Replace the heuristic `proxyBreadth()` with real scoring calculators.

### Backend

| File | Change |
|------|--------|
| `application/market/metrics/breadth.go` | **New** — `scoreBreadth(seriesList, timeframe)` and `scoreBreadthFromCandles(windows, timeframe)` run the real calculators per symbol and average the results. |
| `application/market/metrics/regime_detector.go` | Rewrite: `detectRegime(b breadthValues, vol)` and `regimeScores(b, vol)` now accept all 4 breadth signals. Sideways gets a 0.1 floor so zero-signal defaults to sideways. |
| `application/market/metrics/metrics_service.go` | Store `CandleSeries` in `candleResult`; replace `proxyBreadth` call with `scoreBreadth`. Populate `SidewaysBreadth` and `BreakoutBreadth` in `RegimeMetrics`. |
| `application/market/metrics/backfiller.go` | Replace `proxyBreadth(windows)` + old `detectRegime` with `scoreBreadthFromCandles(windows, timeframe)` + new `detectRegime(breadth, vol)`. Remove old `proxyBreadth` function. |
| `domain/market/regime.go` | Add `SidewaysBreadth` and `BreakoutBreadth` fields to `RegimeMetrics`. |
| `adapters/http/market_regime_handler.go` | Add new fields to DTO and response mapping. |

### Regime scoring multipliers

| Regime | Formula |
|--------|---------|
| Expansion | `breakout × 2 + max(0, vol−1.0) × 3` |
| Compression | `compression × 3` |
| Trend | `trend × 3` |
| Sideways | `sideways × 2 + 0.1` (floor) |

Temperature = 4.0, softmax normalisation unchanged.

## Breadth value computation

`scoreBreadth` runs per symbol:
- **Trend**: `TrendPredictabilityScoreCalculator` → `|score| × (n−1)` to
  recover approximate R² from the tiny `slopeNorm × R²` product.
- **Sideways**: `SidewaysV5ScoreCalculator` → score directly.
- **Compression**: `DetectCompression` → score directly.
- **Breakout**: `DetectBreakout` → `max(BreakoutUp, BreakoutDown)`.

All values are clamped to [0, 1] and averaged across symbols.
