## PR-084: fix(market): derive Market Pulse regime from the composite tape

🎯 Objective

Market Pulse can show **SIDEWAYS — No clear trend (Trend ~5%)** while the composite index
and the rankings grid are clearly grinding up. That is not a data glitch — it is a product
bug. The headline regime today is a **per-symbol score vote** (health-dampened breadth).
Humans read the **merged price path**. Those answers diverge on a messy bid, and the UI
presents them as if they were the same question.

Flip the definition:

| Phrase | New meaning |
|--------|-------------|
| **Market is TRENDING / SIDEWAYS / …** | The **merged market tape** (composite series) scores as that regime under the **same calculators** used on one chart (Trend Predictability, Sideways V5, Compression, Breakout). |
| **Participation** (metrics) | How individual tokens' score mix is distributed — useful, but **not** the headline. |

Also ship **two composites**: equal-weight **median** (outlier-resistant, current chart) and
**volume-weighted** mean (closer to money flow / a "heavier" bar-graph feel). Headline
regime scores the **volume-weighted** series when it has enough data; otherwise median.

🧱 Scope

Backend + frontend + help/COMMON semantics. Prefer additive JSON where possible.

Depends on nothing blocked; can land after current `dev` tip.

---

### Semantics (authoritative)

1. **Composite median** — rebase each symbol's closes to 100 at bar 0; at each timestamp take
   the median. Unchanged from today. Chart label: "Equal weight (median)".
2. **Composite volume-weighted** — same rebase; at each timestamp take
   `Σ(close_s × w_s) / Σ(w_s)` where `w_s` is that symbol's quote-volume proxy over the
   window (`Σ volume×close`). Chart label: "Volume weighted".
3. **Headline regime** — build a synthetic OHLCV series from the chosen composite
   (median of rebased OHLC + summed volume for median path; weighted OHLC + summed volume
   for weighted path), run the same score set as rankings/setups, normalize to a four-way
   mix, dominant → `State`, dominant share → `Confidence`/`prevalence`, mix → structure
   bars. Direction/bias from Trend Predictability `ScoreWithDirection` (fallback: last vs
   first close).
4. **Participation breadth** — keep today's per-symbol `scoreWeights` average (optionally
   without health dampening for the metrics panel, or keep dampening but **never** use it
   for the headline). Exposed under metrics as "Participation", not as the regime bars.
5. **Health dampening** — apply only to the **composite** series (one `ComputeTrendHealth`
   on the tape), not by diluting across 150 tokens. Fixes the `/total` over-penalty.

---

### API (additive)

`GET /api/market/composite`

```json
{
  "timeframe": "15m",
  "symbolCount": 151,
  "points": [ {"t": ..., "v": ...} ],
  "volumeWeightedPoints": [ {"t": ..., "v": ...} ]
}
```

`points` remains the median series (backward compatible).

`GET /api/market/regime` (and `/api/market/state`):

- `regime` / `state` / `label` / `bias` / `prevalence`|`confidence` ← **composite structure**
- `scores` ← composite structure mix (same four keys; meaning changes to tape scores)
- `metrics.trendBreadth` etc. ← **participation** (unchanged field names, new UI copy)
- optional additive: `"regimeSource": "composite_volume_weighted"` | `"composite_median"`

Update `COMMON.md` + `webpage/help/Market_intelligence.md` in the same release.

### Backend work

1. Extend `CompositeIndex` + `CompositeIndexService` to compute both series in one fan-out
   (reuse candle fetches).
2. New pure helper: `BuildCompositeSeries` → `domain.CandleSeries` for scoring.
3. New `ScoreCompositeRegime(series, timeframe) → structure Breadth + State + Bias`.
4. `MarketStateService.Calculate*`: participation from evaluations; state/confidence/label
   from composite score; wire candle provider (already present for vol/dispersion).
5. Drop using participation + multi-token health dampening for headline determination.
6. Tests: rising tape → Trend; flat oscillating tape → Sideways; dual composite math;
   handler JSON additive fields.

---

### Frontend work

1. Regime card: copy that regime is from the **market tape**, not token vote share.
2. Structure bars under headline stay, but subtitle ≠ "prevalence of tokens".
3. Metrics: rename breadth rows to **Participation** (e.g. "Trend participation").
4. Composite card: toggle or dual overlay — Median vs Volume weighted; default show
   volume-weighted when present, with median as secondary.
5. Widget tests for copy + dual series parsing.

---

### Out of scope

- Changing per-symbol rankings badges / sort keys
- Rewriting transition probability model inputs (still can use participation compression)
- Historical backfill of old regime history under the new definition (new points only)

🚀 Result

A green composite and a green rankings grid can no longer sit under "SIDEWAYS — No clear
trend" unless the **tape itself** scores sideways. Market Pulse finally answers the
question humans ask when they glance at the page.
