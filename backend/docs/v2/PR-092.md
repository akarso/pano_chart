## PR-092: feat(signal): scorecard API

🎯 Objective

Expose hit-rate scorecards (vs baseline) over graded signals from PR-091 so the
app can show reliability chips (PR-093) and Track E can compare algorithms.

See ROADMAP Track B — PR-092.

🧱 Scope

- `application/ports/scorecard_store.go` — aggregate / summary / baseline port
- `infrastructure/signal/scorecard_store.go` — SQL INNER JOIN + admin-rule exclude
- `application/signal/scorecard_service.go` — deciles, stable `since` buckets,
  kind allowlist, deterministic baseline excluding scored label (`null` when
  no comparison set); no separate long-lived baseline map
- `infrastructure/signal/redis_cached_scorecard.go` — 10m Redis + singleflight
  (detached context); path-escaped keys; normalized kind; whole card cached
- `adapters/http/scorecard_handler.go` — `GET /api/scorecards`, `/summary`
- `cmd/api/main.go` — wire when signal DB is available
- `COMMON.md` — endpoint contracts
- Tests: unresolved crowding, nullable baseline, known non-zero baseline,
  summary derivation, SQLite decile boundaries, Redis `Nil` miss, kind case

Out of scope: Flutter UI (PR-093); changing outcome rules (PR-091); auth /
rate-limit on the public market surface (follow-up).

1️⃣ Scorecard

`Get(kind, label, timeframe, sinceRaw)` aggregates gradable outcomes in SQL
(no 10k hydrate). `ExcludedFromHitRate` rules never enter the denominator.

Baseline: full same-kind (+ timeframe) hit rate in the window, excluding the
label under test. Sole-label / empty comparison → JSON `null` (not `0`).
Stored only inside the Redis card so hit rate and baseline share one 10m TTL.

2️⃣ Endpoints

- `GET /api/scorecards?kind=&label=&timeframe=&since=30d`
- `GET /api/scorecards/summary?timeframe=&since=30d` → `{ items, since, sinceRaw }`

Redis cache key uses path-escaped fields + stable relative since token (`30d`)
or exact absolute RFC3339Nano; TTL 10m. Absolute instants older than 10 years
are rejected. Shared flights are refcounted: a canceled caller returns
immediately, and the last waiter cancel abandons the work context (releases
the compute slot). Redis
hard GET errors are logged and fail the request (no SQLite fallback). Soft-fail
when signal DB down (endpoints not registered → 404).

✅ Definition of Done

- [x] SQL aggregates; unresolved rows cannot crowd out graded ones
- [x] Summary per-(kind,label); baselines from one GROUP BY (no N queries)
- [x] Baseline excludes scored label; `null` when no comparison; known fraction
- [x] Hit rate + baseline share one Redis TTL (no 1h baseline skew)
- [x] `since=30d` a second apart shares one Redis key; `Badge`/`badge` same key
- [x] Absolute since: exact SQL bound and matching cache key (no cross-window hits)
- [x] Get aggregate + baseline in one SQL statement
- [x] Request-scoped SQLite + single in-flight scorecard compute
- [x] SQLite summary baselines `0.5` / `1.0`; decile boundaries
- [x] Handler: a canceled or deadline-expired caller returns immediately (499 / 504) and does not wait out the shared flight. A remaining waiter still receives the card. Redis GET cancel stays `context.Canceled` (499), not 502.
- [x] Absolute `since` older than 10 years is rejected, same cap as relative durations
- [x] COMMON.md documents both endpoints
- [x] gofmt / go vet / tests clean

🚀 Result

After outcomes exist, curl returns non-empty scorecards; summary powers UI chips.

📝 Implementation notes

- Baseline is a same-kind empirical chance floor from the signal log (not a
  full counterfactual re-grade of random symbols without prior emissions).
- No row-limit truncation on the scorecard window; aggregates scan the full
  `since` range via INNER JOIN.
- `since` accepts exact `Nd` / `Nh` / `Nm` / `Ns` or RFC3339 within 10 years. Trailing garbage
  rejected. Index `(kind, timeframe, emitted_at)` supports kind baselines.
