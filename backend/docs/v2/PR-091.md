## PR-091: feat(signal): outcome evaluator job

🎯 Objective

Grade resolved signals after their horizon elapses so Track B can build
scorecards (PR-092). Pure success rules live in domain; a 5-minute job fetches
forward candles (or the composite tape for market-wide signals), computes path
metrics, and writes the `outcomes` table.

See ROADMAP Track B — PR-091. Depends on PR-090.

🧱 Scope

- `domain/signal/outcome.go` — `Outcome`, path stats, rules, `ExcludedFromHitRate`
- `domain/market/regime_at.go` — half-open `RegimeAt` (Tracker boundary-safe)
- `application/ports/signal_repository.go` — `UnresolvedReady`
- `infrastructure/signal/sqlite_repository.go` — ready SQL filter by TF duration
- `application/signal/evaluator.go` — 5m job, refuse-to-resolve, tape cache/tick
- `cmd/api/main.go` — start evaluator when signal DB is available
- Tests under `tests/domain/signal`, `tests/domain/market`, `tests/application/signal`

Out of scope: scorecard API (PR-092); changing signal writers / labels (PR-090);
HTTP / COMMON.md (no new JSON). Historical composite store (tape beyond latest N)
is still deferred — permanent misses drain as `path_unavailable`.

1️⃣ Success rules

| Label | Success when |
|-------|----------------|
| `trend_up` / `trend_down` | sign(fwd) + `MaxAdverse < 2` |
| `sideways` / `range` | never closed outside `[range_low, range_high]` by `> 0.5×ATR` |
| `compression` | horizon range ≥ `1.5×` emission window range |
| `breakout_up` / `breakout_down` | `MFE ≥ 2 && MAE < 1` (direction-aware) |
| `regime:trend` / `regime:sideways` | ATR/price thresholds + bias |
| `transition:X` | regime at horizon equals X |
| other (`gain`, `regime:expansion`, …) | `Rule=unsupported` (excluded from hit-rate) |

Administrative rules (always `Success=false`, **exclude from PR-092 denominators**
via `ExcludedFromHitRate`): `unsupported`, `invalid`, `insufficient_context`,
`path_unavailable`.

2️⃣ Evaluator semantics

- **Ready fetch:** `UnresolvedReady(now, limit)` — SQL
  `emitted_at + horizon_bars×tf_ns ≤ now` for known TFs only. Over-fetch
  so retryable skips do not starve other ready rows.
- **Invalid TF:** `UnresolvedInvalidTF` queries unknown timeframes directly
  (not a scan of mixed unresolved). Shares `MaxPerTick` with ready grading;
  first invalid pass is capped at `MaxPerTick/2` so ready is never starved for
  a full tick; leftover after ready returns to invalid drain.
- Timeframe storage / SQL use the same trim+lower rules as `domain.NewTimeframe`
  (`"1H"` / `" 15m "` grade as ready, not `RuleInvalid`).
- **Path-independent labels:** `transition:*` and unsupported (`gain`,
  `regime:expansion`, …) grade before any candle/tape load (`NeedsPath`).
- **Symbol path:** `GetSeries` then clip to half-open `[EmittedAt, horizonEnd)`;
  require `len(closes) ≥ HorizonBars` or leave unresolved.
- **Market-wide:** one `CalculateTape` per timeframe per tick (prefetch). If
  required bars `> 500` or tape oldest `> EmittedAt` → `path_unavailable`.
  Incomplete but recoverable → leave unresolved.
- **ATR:** rules that need ATR leave unresolved when `atr ≤ 0` after fallbacks
  (tape uses emit-time `SimpleATR`-equivalent, not mean range).
- **Transition:** regime lookup miss / empty history → leave unresolved (no
  false-negative `Success=false`).
- **RegimeAt:** half-open `[Start, End)` so Tracker `CloseCurrent(ts)+Append(ts)`
  boundary belongs to the new regime.

🚀 Result

After signals age past their horizon, `outcomes` fills. Ready signals are not
blocked by not-yet-ready longer TFs. Unrecoverable market-wide windows and
invalid TFs drain administratively; missing candles / ATR / regime history
retry next tick.

📝 Implementation notes

- ROADMAP’s `Unresolved(before=now−horizon)` is superseded by `UnresolvedReady`
  (exact per-row horizon). Legacy `Unresolved` remains for invalid-TF drain.
- No historical composite store yet: delayed market-wide signals outside the
  latest-`N` tape window become `path_unavailable` rather than wedging the queue.
- PR-092 **must** filter `ExcludedFromHitRate(rule)` (or equivalent) so
  `unsupported` / administrative outcomes do not poison KindRegime / KindBadge
  hit rates.
- `breakout_down` mirrors `breakout_up` with direction-flipped MFE/MAE.
