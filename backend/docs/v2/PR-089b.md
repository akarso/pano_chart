## PR-089b: feat(evaluation): migrate readers onto evaluation store

🎯 Objective

PR-089a wrote evaluations into Redis on a schedule. This PR switches Market
Pulse (via `RankingsEvaluationProvider`) and setups onto that store so a warm
cache means zero rankings/scoring work for participation. Notifications keep
their existing `MarketState` API and benefit automatically.

See ROADMAP Track A — PR-089b.

🧱 Scope

- `domain/evaluation_refresh.go` — `EvaluationStaleAfter` (= `2 × refresh interval`)
- `infrastructure/market/rankings_evaluation_provider.go` — prefer store `Get`;
  miss/stale/empty/algo/transport/future-at → rankings fallback (`DoChan`);
  transport fails **open** (Redis down must not take Market Pulse offline;
  singleflight coalesces)
- `application/setups/service.go` — prefer `GetSymbol(tf, sym.String())`;
  candles for volume/volatility; live trend overlay on trailing **110** bars
  (rankings precision), not the full setup 200-bar series
- `domain/evaluation_refresh.go` — `EvaluationStoreFresh` (rejects negative age)
- `adapters/http/market_{handler,regime_handler}.go` — stable client error for
  `ErrEvaluationStoreUnavailable` (still used if callers surface it)

Out of scope: `?fresh=0` on GetRankings HTTP; Prometheus counters; COMMON.md.

1️⃣ Reader freshness

A store Put is usable while `EvaluationStoreFresh(at, now, tf)`:
`0 ≤ age ≤ EvaluationStaleAfter(tf)`. Future / zero `at` is not fresh.
Also rejected (treated as miss → live compute):

- empty array (`[]` + fresh `at`) — must not poison Market Pulse
- `AlgoVersion != domain.AlgoVersion` (including empty)
- `ErrEvaluationNotFound`

Refresher only writes `15m` / `1h` / `4h` / `1d`. Setups on `1m` / `5m` always
miss then score (intentional; not a writer cadence).

2️⃣ Fail policy

| Reader | Miss / stale / empty / algo / future-at / transport | Redis transport |
|--------|-----------------------------------------------------|-----------------|
| Provider | fall back to rankings (`DoChan` + select on caller ctx) | **fail open** → rankings |
| SetupService | fall back to SymbolScorer | fall back to SymbolScorer |

Cancelled Market Pulse / regime callers return on `ctx.Done()` while the shared
rankings flight continues under `WithoutCancel` (same pattern as
`RedisCachedComposite.CalculateTape`). Flight results are deep-copied per waiter.

Market Pulse / regime HTTP still map `ErrEvaluationStoreUnavailable` to a stable
message if a caller surfaces it; the provider itself no longer returns that
error on Redis transport (fail-open).

3️⃣ Warm setups: store + live trend overlay

Store magnitudes for Compression / Sideways / Breakout. Before
`dominantRegime` / `buildContext`, `overlayLiveTrend` replaces Trend
Predictability with live `ScoreWithDirection` on the **trailing 110 bars**
(rankings default precision / sparkline length), not the full setup 200-bar
fetch used for volume/volatility. Direction is passed via `DirectionBias`
(one ScoreWithDirection call). Overlay errors are a miss → scorer.

4️⃣ Observability

Info logs only for non-hits (hits are silent to avoid notification/Market Pulse
spam):

- `[eval] provider reason={miss|stale|empty|algo|transport} tf=…`
- `[eval] setup reason={miss|stale|algo|transport|overlay} symbol=… tf=…`

(`reason=empty` is provider-only: `GetSymbol` has no empty-success path.
`reason=overlay` is setup-only: ScoreWithDirection failed on a store hit →
scorer fallback.)

Warm setups call ScoreWithDirection once in `overlayLiveTrend` and pass
`DirectionBias` into `dominantRegime` (no second compute). Overlay errors are
a miss, not a keep-store-TrendScore path.

Singleflight waiters receive a deep copy (structs + Sparkline backing arrays).

🚀 Result

On a warm evaluation store, Market Pulse `Calculate` participation reads Redis
only (tape still uses the PR-086 composite cache). Setups skip SymbolScorer when
the symbol snapshot is fresh and algo matches. Disable writer with
`PC_EVAL_REFRESH=0`; readers still attempt the store and fall back.

📝 Implementation notes

- Stale threshold shares `domain.EvaluationStaleAfter` with TTL planning
  (`EvaluationStoreTTL` floors at 10m so readers still see data between ticks).
- Candle I/O remains the floor for setups (volume/volatility); market modifier
  still calls `Calculate` (another store `Get`) when wired.
- Optional `?fresh=0` rankings path deferred.
- Hit/miss Prometheus metrics deferred; hits stay silent at info.
- Availability: provider transport fails open to rankings; page on elevated
  `reason=transport` rate if Redis outages become chronic.
