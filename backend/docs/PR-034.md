# PR-034: MetaScore Engine (Enhanced Version)

## Status
Proposed

## Objective

Introduce a flexible and extensible MetaScore Engine to:

- Compose multiple normalized subscores into one unified score
- Support structural detectors (Sideways v5, Breakout, Trend)
- Allow runtime weight tuning
- Support timeframe-specific profiles
- Allow subscores to expose internal metadata
- Support confidence-aware composition
- Enable future advanced user-configurable scoring

This PR defines infrastructure only.
No specific detector logic included.

---

# 1. Design Principles

1. All subscores return normalized values ∈ [0,1]
2. No internal hardcoded global multipliers
3. Subscores may internally segment data (e.g., spike detection)
4. MetaScore composition must remain generic
5. Confidence must be supported but optional
6. Timeframe configuration must not fork algorithms

---

# 2. Core Types

## 2.1 SubscoreResult

```go
type SubscoreResult struct {
    Value      float64            // normalized [0,1]
    Confidence float64            // normalized [0,1]
    Meta       map[string]float64 // optional breakdown data
}
Rules:

Value must be clamped to [0,1]

Confidence defaults to 1.0 if not used

Meta is optional but encouraged

Purpose:

Allow shock/recovery logic

Allow debugging and UI breakdown

Allow confidence-based weighting

Subscores must:

6. Score Execution Flow
Compute all subscores

Clamp Value and Confidence

Apply confidence adjustment (optional)

Normalize weights

Apply composition mode

Clamp final score to [0,1]

Return final score + breakdown

7. Confidence-Adjusted Weights
If enabled:

effectiveWeight = baseWeight * result.Confidence
Purpose:

Penalize unstable structures

Reduce impact of low-confidence detections

Support spike recovery logic

If disabled:

BaseWeights are used directly

8. Composition Implementations
8.1 Weighted Additive
score = Σ (w_i * s_i) / Σ(w_i)
Stable, smooth ranking.
Default for development.

8.2 Weighted Multiplicative
score = Π (s_i ^ w_i)
Strict filtering.
One weak dimension collapses score.

Useful for Top-20 ranking.

8.3 Hybrid Structural
Designed for structural detectors.

Example:

structure = pow(CCS, w1) * pow(OQS, w2)
modifier  = 1 + w3*(VOS - 0.5)
score     = structure * modifier * pow(DCS, w4)
Structure dominates.
Modifiers influence but do not override.

Recommended for Sideways v5 and Breakout.

10. Shock & Recovery Compatibility
MetaScore Engine does NOT implement shock logic.

However:

Subscores may:

Detect spikes

Segment internally

Adjust Value

Lower Confidence

MetaScore may:

Down-weight unstable structures

Preserve composability

Shock logic belongs inside structural subscores (Sideways v5).
